# 调用规则：AutoScript 脚本生成流程

本文件定义 AI 调度脚本的触发条件、执行流程、失败处理。AI 必须严格遵守。

## 0. 解释器约定（重要）

所有命令一律使用项目 venv 解释器执行，**不要用系统 python**（venv 含全部依赖 + OCR 引擎）：

```bash
.venv\Scripts\python.exe <脚本> <参数>
```

下文命令中的 `python` 均指 `.venv\Scripts\python.exe`。工作目录 = 项目根（D:\Project\script\lrjl\jy-frame-lrjl\jy-frame-engine\autoScript）。

## 1. 触发条件

当用户输入包含以下意图时，启动脚本生成流程：
- "写脚本"、"生成脚本"、"自动刷"、"自动化"
- 指定了游戏/APP 和具体任务（如"刷副本"、"做日常"）

## 1.2 游戏工作目录与 WS 录制流程（2026-09-26 定稿，与下文 Step 流程冲突时以本节及 §1.3/§1.4 为准）

### 游戏工作目录（games/<游戏名>/）

首次接入新游戏（按**包名+名称+画面 phash** 判同，无匹配即新建）时创建，包含 4 个 Lua 文件（Lua table 格式，可直接复制进脚本使用）：

| 文件 | 内容 | 格式参考 |
|------|------|---------|
| `特征.lua` | 该游戏全部特征行（按模块组织的 Lua table） | doc-flat 各指令文档 |
| `UI.lua` | 该游戏 JUI 设置面板定义（uiConf） | `engine\JUI.lua` 实现方式 |
| `conf.lua` | **conf 全量配置** | doc-flat《04-conf变量说明》 |
| `vars.lua` | **vars 预定义** | doc-flat《05-vars变量说明》 |

**conf/vars 铁律（2026-09-26 用户定稿）**：
1. **conf 所有配置都要有**：doc-flat《04-conf变量说明》的 11 大类配置项全部写齐（平台/框架设置/任务执行/防卡死/浮窗等），不允许只写最小骨架
2. **卡屏检测等辅助配置可先不开启**：配置项必须存在，但开关类默认关闭（`卡屏检测=false`、`启动线程=false` 等）
3. **vars 必须先定义再使用**：特征行的 变量赋值/执行条件/writePoint 用到的变量，必须先在 vars.lua 中定义
4. **录制中发现新变量需求**：先回补 vars.lua 定义，再继续使用

### WS 点击（替代 adb 裸点击）

- 所有点击操作通过 JY-Frame cloud WS 通道（`adb forward tcp:19301 tcp:9300`）发特征行执行（pageTest/action），**禁止 adb 裸坐标点击**
- 回包判定：`op=log` 出现"找到坐标" = 特征命中；`op=ok` = 执行成功；`op=warn` = 失败原因
- **特征即时沉淀**：点击验证成功的特征行立即写入该游戏 `特征.lua`（操作与验证一体，不做事后补采样）
- 前置：模拟器已装测试助手（云控端）且云控已启动（9300 监听）；未启动则先启动测试助手

### 图色命令与模块测试

- 特征行按语义选 ff 域（ps/ft/fc/pic/ocr/fs/move/cjRand/yolo...），参数格式严格按 doc-flat 对应指令文档；doc-flat 全部命令均可用（06-指令索引）
- 每个任务模块写完必须 WS pageTest 真机实测：运行成功 + 达到预期效果（命中日志/退出码/画面效果）才算完成；失败回炉重做

## 1.3 现成脚本迁移与模块组织规则（2026-09-26 龙迹之城迁移复盘定稿）

来源：《龙迹之城》按键精灵脚本迁移复盘（240 特征组 / 1206 特征行 / 3 张调度表 / 14 个自定义函数）。与 §1.2 并存，冲突时以本节为准。

### 1.3.1 坐标系（以游戏实际运行方向为准）

1. 模拟器设置方向不等于游戏方向：启动游戏观察是否自转（龙迹之城竖屏设置下自转横屏 → 基准 1280x720）
2. 三处必须一致：`conf["开发比例"]` = `devices.yaml design_resolution` = 模拟器实际运行分辨率
3. 现成脚本的旧坐标系实测值（按键竖屏 720x1280）只作界面相对位置参考，**未经 WS pageTest 验证禁止启用**
4. 换方向/换游戏时四件套一并对齐：conf / 特征.lua 头注释 / devices.yaml / UI.lua 高度

### 1.3.2 模块九类命名规范（240 组归纳，新组按类入位）

| 类 | 组名示例 | 说明 |
|----|---------|------|
| 通用共享 | 通用 | 跨模块复用界面元素；同名特征被 `ff="ty"` 按名引用 |
| 进入链 | 进入游戏/选区/登录游戏 | 只负责到达主界面，遇引导态转交章节任务 |
| 任务调度表 | 任务列表/BOOS任务/面板任务 | `["任务列表"]=true` 标记，行=模块名（§1.3.5） |
| 面板功能 | 英雄/转生/合成/锻造/符文/商城/神坛… | 按面板子功能命名（约 44 组） |
| 活动奖励 | 开服奖励/每日累充/领取红包/打宝金库… | 领取类任务（约 25 组） |
| BOOS战斗 | 万妖/战灵BS/整点boos/狂暴战场/打修罗… | 限时/整点活动（约 60 组） |
| 挂机 | 玛雅/等级/埋骨/试炼/龙眠/神龙大陆… | 地图刷怪（约 50 组） |
| 历练 | 历练/历练任务/历练答题/自动历练… | 专项任务链（约 20 组） |
| 服务兜底 | 通用弹窗/立即使用/前往治疗/通用任务退出/空任务 | §1.3.4 |

预留组：`taps["手指"]`（手指哨兵，编译期自动注入业务模块首行）

### 1.3.3 特征行两种特殊 ff 语义（必会）

- `ff="ty"`：引用 taps["通用"] 组同名特征，**不重复写 ps 串**
  （如 `{"主界面",5,ff="ty",isClick=false,wait=0,out=true}`）
- `ff="nil"`：纯逻辑行——不识别不点击，仅用于 运行后方法 路由 / 变量赋值 / 执行条件（调度表抽象行、空任务都用 nil）

### 1.3.4 三层兜底体系（任务退出保障，新模块必须挂齐）

1. **弹窗层**：`通用弹窗` 组集中全部弹窗关闭行（out=true），业务行 `notFun="通用弹窗"`
2. **业务兜底层**：`通用任务退出` 组末行 `{"主界面",ff="ty",out=true}`，串联 立即使用/前往治疗/前往活动 子链
3. **空任务**：`{"空任务",ff="nil",out=true}` —— 调度表首行占位/立即退出

### 1.3.5 调度表与任务参数

- 主调度表"任务列表"= 主循环行集；分类表（BOOS任务/面板任务）由主表行 运行后方法 进入
- 任务参数元组语义（9 元，按键原注释）：`{启动方法, 执行方法, 执行模式, 执行间隔时间, 进入任务超时时间, 是否有对应设置, 执行次数, UIID, 任务执行前操作}`
- 时间/状态门控的执行条件引用**注册函数名**（Battlefield/Hero/mbcheck —— 对应 JY addFun 机制），禁止在行内堆叠复杂条件
- 组级时间字段：`循环次数`（行扫描轮数）/ `强制休息`（组间休息 ms）/ `超时时间`（秒）
- 组内可设 `["任务界面"]` 子表：界面打开探测行（isClick=false, wait=0），打开失败不进入业务行（前往治疗/英雄殿进阶 先例）

### 1.3.6 变量赋值四类型（先定义后使用扩展）

| 类型 | 意义 | 生命周期 | 例子 |
|------|------|---------|------|
| 1 | 任务变量 vars | 切号重置 | `{1,"任务变量","战灵boos",0,"s",false}` |
| 2 | 框架配置 conf | 脚本运行期 | `{2,"当前任务","","==","新手任务"}` |
| 3 | 持久化 fileGetUser/filePutUser | 跨账号持久 | 英雄时间/地图序号（不在 vars.lua 定义，注释标注） |
| 7 | UI 设置 getUISet | 用户配置 | `{7,"治疗减冷却","","==",true}` |

规则：赋值/执行条件/zxtj/ocrCompare 引用的所有变量名必须先出现在 vars.lua（类型 3 除外）；`ff="ft_wv"/"ft_res"/"ocr"` 特征行自动写 vars（wp/writePoint 指定键）

### 1.3.7 现成脚本迁移流程（2026-09-26 已验证）

1. 源码转码（GBK→UTF8）后先修复**源脚本笔误**再转换（龙迹之城实测 3 处：丢 `}` / 多 `)` / 两句粘行）
2. 按四类剥离：vars/taps/conf/UI；Import 外部文件与自定义函数**只记录清单不迁移**（函数接入待定——HJG.addFun 注册名被 运行后方法/执行条件 引用，接入时逐个映射到 JY 寄存器）
3. `pic_s/pic` 类特征依赖附件图片（Attachment:*.png，如背包元宝），迁移时必须一并收集图片资源，缺失的行禁止启用；OCR 依赖字库文件同理
4. 迁移产物 = 参考基线：模块结构 / 字段语义 / 组级参数可直接复用；特征坐标与色点必须 WS pageTest 验证回写后才可启用

## 1.4 自动生成统一流水线（2026-09-26 定稿）

### 心智模型：特征工厂 + 任务汇编器

三层职责（澄清"特征写进 特征.lua 还是编译产物"的歧义）：

| 职责 | 载体 | 生命周期 |
|------|------|---------|
| 特征库存 | 特征.lua | 录制期即时回写，逐条 WS 验证后入库存 |
| 任务编排 | state/<run_id>.json | 录制期状态机记录（Step 7） |
| 组装编译 | compile.py | 编排 + 库存 → 扫描式调度表 Lua 模块 |

### 四层流水线（§2 各 Step 的归属地图）

| 层 | 职责 | 对应 Step |
|----|------|-----------|
| 层0 就绪 | 方向/分辨率三处一致、前台包名、WS 通道 | §1.3.1 + Step 0/1 |
| 层1 特征生产 | 截图分析 → bbox 采样(hit_rate≥0.9) → WS 发特征行 → 命中+画面验证 → 写回库存 | Step 2/4/5/6 |
| 层2 任务组织 | 状态去重、转移记录、run_once 幂等、兜底三件套（out 锚点 / notFun=通用弹窗 / 手指哨兵） | Step 2.5/3/7 |
| 层3 编译+实测 | compile.py 组装扫描式调度表 → WS pageTest 逐模块 | Step 9/10 |

每模块编译语义固定（禁止按录制时间顺序串链）：行1-N = 弹窗清理行最前 → 业务推进行居中 → 兜底退出锚点（out=true）最后。

### 两种模式

1. **探索模式（新游戏）**：无先例，Step 0-10 全流程顺序生产（层1 → 层2 → 层3）
2. **迁移模式（现成脚本）**：按 §1.3.7 四类剥离进库存后**跳过层2**，按调度表入口顺序逐模块 WS 验证激活：命中+画面验证 → 旧坐标系实测值回写成当前基准 → 模块通过即激活；pic_s/pic 行先补附件图片；引用未接入自定义函数的 `运行后方法` 行暂挂起，函数接入后统一激活

## 1.5 开发流与测试修复流（2026-09-26 定稿）

### 流程 A：功能开发流
即 §1.4 四层流水线（探索/迁移模式）。收口标准 = 模块 pageTest 通过：命中"找到坐标"日志 + 退出码语义符合预期。

### 流程 B：测试修复流（回归/修 bug）

1. **有提示**（用户报症状：卡在 X 界面 / 点了没反应 / 一直转圈）：
   症状 → 嫌疑模块 → 单模块 pageTest 复现 → 日志落盘 → 判据表定位到行 → 修复 → 回归重跑
2. **无提示**（例行回归）：
   按 3 张调度表遍历测试矩阵（任务列表/BOOS任务/面板任务 每入口 taskTest + 每模块 pageTest）
   → 批量采集退出码 + op=log → 异常项按判据表出列 → 修复 → 回归

### 日志判据表（WS op=log/退出码 → Bug → 修复动作）

| 日志判据 | Bug 类型 | 修复动作 |
|---------|---------|---------|
| 退出码 5 + 全程无"找到坐标" | 特征全未命中（界面改版/坐标漂移） | 层1 回炉采样（§1.4） |
| "未命中特征 -- 行#" 仅个别行 | 单特征失效（坐标/色点错） | 该行重采样；对照 degree 定改阈值还是换点 |
| 未找到任务 / 未找到<页>页面 | 调度表行名 ≠ taps 组名 | 改编排/改 key |
| 未找到通用参数配置【x】 | ty 引用名错/通用组缺行 | 补通用组 |
| 未找到操作类: x | ff 域写错/未注册 | 改 ff |
| [x] 不满足执行条件 -- #n: … | 条件逻辑/变量值错 | 修条件或变量定义 |
| 反复命中但不退出 | 兜底缺失/out 锚点失效 | 补兜底三件套（§1.3.4） |
| 【失败】等待时间 | 任务界面子表探测行失效 | 重采探测行 |
| 写入变量 类型[键]=值 与预期不符 | 赋值值/时机错 | 修变量赋值参数 |
| 卡屏/游戏不在前台退出 | 环境类（非脚本 bug） | 环境修复，不入脚本判据 |

### 日志能力现状与增强（2026-09-26）

- **已具备**：命中轨迹（【ff】找到/点击坐标+行名+任务链）、未找到操作类/页面/通用参数点名、
  执行条件不满足明细（-- #n 原因）、变量赋值写入日志（写入变量 类型[键]=值）、
  退出码回传、print 全量桥接 op=log
- **本次增强**（engine/JY，已同步主仓）：①未命中行级日志（行号 + degree 阈值）
  ②执行条件"满足"对称日志
- **待增强**：未命中真实相似度上报（finder 链当前二进制返回，改动大暂缓）
- 所有日志受 `conf["是否打印输出"]` 门控（调试开、生产关）

### 修复闭环要求

复现必须日志落盘（`logs/<run_id>_<模块>.log`，op=log 全量保存）→ 判据表定位到行 →
修复（特征级=回炉采样 / 编排级=改模块结构与兜底）→ 回归 pageTest 通过 → 回写特征.lua 库存。

## 2. 执行流程

### Step 0：环境检查

```bash
.venv\Scripts\python.exe scripts/adb.py doctor
```

检查通过后继续；失败则向用户报告问题，不盲目继续。

### Step 1：创建运行记录

确定 run_id（`run_<时间戳>`），后续状态写入 `state/<run_id>.json`。结构见 scripts/models.py 的 `new_run()`。
**同时确定游戏包名**：游戏在前台时用 `foreground` 读取，写入 run JSON 的 `package` 字段（后续前台守护依赖它）。

```bash
.venv\Scripts\python.exe scripts/adb.py foreground --device <device_id>   # 取当前前台包名
```

### Step 2：截图分析（先守护前台）

**每次截图前确保游戏在前台**——不在（被弹回桌面/锁屏/切后台）则自动拉起并等画面稳定：

```bash
.venv\Scripts\python.exe scripts/adb.py ensure --device <device_id> --package <package> [--wait-ms 15000]
```

- 返回 `relaunched=true` 时说明执行了拉起：等待加载完成后**重新分析界面**（可能回到登录/主界面，需按职责分层重新走进入链，并记 anomaly type=offline）
- `stable=false`：拉起后画面迟迟不稳（加载超时），等待后再试一次，仍失败报用户

```bash
.venv\Scripts\python.exe scripts/adb.py screenshot --device <device_id> --output screenshots/<run_id>_001.png
.venv\Scripts\python.exe scripts/analyze.py --image screenshots/<run_id>_001.png
```

获取界面元素列表和语义标签。设备未指定时先 `.venv\Scripts\python.exe scripts/adb.py devices` 选择。
返回 JSON 中 `vision_available=false` 时说明视觉模型 Key 未配置或调用失败（自动降级 OCR），提示用户设置 AGNES_API_KEY（见 config/models.yaml）可提升识别质量，但不阻塞流程。

### Step 2.5：新游戏任务体系分析（首次接入必做）

该游戏无历史 run/state 时必做，用于决定录制优先级（依据 knowledge/新手引导与章节任务设计.md）：

1. **探测**：主界面截图 analyze → 打开任务/活动/福利面板分别截图 analyze，视觉判断：
   - 有无**主线/章节任务**入口及进度（任务面板文案：主线/章节/关卡）
   - 有无**强制引导**信号（遮罩+手指高亮+跳过按钮，见 §6 识别信号）
   - 有无**成长型任务**（七日/新手奖励/升级）与日常活动列表
2. **决策**（写入 run JSON 的 `task_survey` 字段）：
   - 有主线/章节/强制引导 → 录制顺序 = **章节任务链优先**（推进型录制、run_once），日常后置
   - 无引导但有成长型任务 → 成长型按普通任务采样，与日常并列
   - 都无 → 直接录挂机/日常模块
3. 探测中若已处于强制引导态：直接按 §6 引导态行为准则开始录章节链，探测顺延到引导完成后补做

### Step 3：任务规划

基于用户目标和当前界面，AI 自主规划：
- 当前在哪个界面（scene_label）
- 下一步应该点哪个元素（优先选 confidence 高且 is_primary 的元素）
- 点击后期望到达什么界面（expected_scene）

每步决策必须写明 reason（可追溯）。

**职责分层（新手阶段必须遵守，详见 knowledge/新手引导与章节任务设计.md）**：
- **进入游戏**只负责到达主界面（启动弹窗/实名/公告清理）——录制中遇到引导界面立即停止进入游戏链，转交章节任务
- **章节任务**专职处理新手引导/主线推进；引导完成回主界面后 TaskNode 标记 `run_once: true`
- 录制顺序：先章节任务（引导），后日常任务

### Step 4：特征采样

```bash
.venv\Scripts\python.exe scripts/feature.py sample --image <截图> --bbox <x1,y1,x2,y2> --count 3
```

对目标元素采样稳定色点。hit_rate < 0.9 时重新采样（可用 --count 换点数）。

### Step 5：执行操作（WS 特征行执行，禁止 adb 裸点击）

采样完成后通过 JY-Frame cloud WS 通道发特征行执行（通道与 Step 10 相同）：
`adb forward tcp:19301 tcp:9300` 后 WS 发
`{modle:1, page:<模块名>, taps:{<模块名>:{<特征行>}}, conf, vars}`（模板 tests/_ws_color_full.py）

- 回包判定：`op=log` 出现"找到坐标" = 特征命中；`op=ok` = 执行成功；`op=warn` = 失败原因
- **点击即验证**：命中 + Step 6 画面验证通过 → 特征行立即写入 特征.lua 对应模块分组（操作=采样=验证一体，不做事后补采样）
- 文本输入/滑动同样走 WS 特征行（ff="input"/"move"），一律禁止 adb 裸坐标点击

**禁用 keyevent back 回主界面**：部分游戏按返回会弹"退出游戏"确认框甚至直接退出。
退出界面一律找界面内关闭控件（X/关闭图标）采样点击；确无关闭控件才允许 back，
且必须 postclick 验证未触发退出确认（见 knowledge/新手引导与章节任务设计.md §9）。

坐标一律使用截图中元素的真实像素坐标，**AI 不得自行换算坐标**（编译时由 coordinate.py 统一处理）。

### Step 6：验证结果

**标准验证（必用 verify.py，覆盖单次画面对比）**：

```bash
.venv\Scripts\python.exe scripts\verify.py postclick --device <id> --before screenshots/<run_id>_002.png --final-shot screenshots/<run_id>_003.png
```

postclick 自动循环截图等画面稳定（寻路/打怪类适用），输出 verdict：
- `no_change`：画面没变 → 等 1s 换点重试（最多 2 次）
- `changed_stable`：变化后稳定 → 读 `task_changed`（任务栏文本变化=任务推进，打怪/任务类游戏的关键信号）与 `mask.detected`（弹窗关键词）
- `still_moving`：仍在变化（寻路中）→ 加 `--max-wait` 继续等

任务栏区域默认左上 (0,180,340,480)，可用 `--task-region x1,y1,x2,y2` 按游戏调整。

补充手段（postclick 无法判定时）：

```bash
.venv\Scripts\python.exe scripts\analyze.py --image screenshots/<run_id>_003.png
```

三重验证：
1. 画面变化检测（phash_distance > 5 说明画面变了）
2. 语义验证（scene_label 是否到达 expected_scene）
3. 元素验证（预期元素出现/消失）

**等待类转移（type=wait）**：不点击、只等待界面出现时，必须连续确认 ≥2 次（多次截图 scene_label 稳定）才算成功，转移记录中写 `"verify_count": N`（确认次数）——编译器据此生成 outCount 连续检测退出（M10）。

### Step 7：记录状态

将 ScreenState / Transition / TaskNode / Anomaly 写入 `state/<run_id>.json`：
- 状态去重：phash 汉明距离 < 5 且 scene_label 相同 → 复用 state_id（用 models.find_duplicate_state）
- 每个转移记录 action、success、duration_ms
- 一次性任务（如每日签到，挂机多轮只需执行一次）在 TaskNode 写 `"run_once": true`——编译器据此生成 执行条件+变量赋值 幂等对（M11）

### Step 8：循环

重复 Step 2-7 直到任务完成。**每轮开始都执行 Step 2 的前台守护**（ensure，游戏中途被杀/弹回桌面时自动拉起）。检测到状态循环（A→B→A 出现 2 次）时跳出并记录异常。

### Step 9：编译输出

```bash
.venv\Scripts\python.exe scripts/compile.py --run-id <run_id> --platform lua --output output/<名称>.lua
```

编译前可用 `.venv\Scripts\python.exe scripts/compile.py inspect --run-id <run_id>` 检查状态机摘要（含 warnings）。
编译后向用户报告输出路径、模块数、特征数、warnings 内容。

组装职责（与 §1.4 一致）：compile.py 读 run JSON 编排（状态机/转移/run_once）+ 特征.lua 特征库存 → 生成扫描式调度表 Lua 模块：弹窗清理行最前 → 业务推进 → 兜底退出锚点（out=true），禁止按录制时间顺序串链。

### Step 10：真机 WS 实测（编译产物必须验证）

编译出的 Lua 模块通过 JY-Frame cloud 通道真机实测（模板 tests/_ws_color_full.py）：

1. **通道**：设备端 JY-Frame（autolua2 引擎，`cloud.open{port=9300}`，dispatch 入口）；
   PC 端 `adb forward tcp:19301 tcp:9300`，WS 发 `{modle:1, page:<模块名>, taps:<产物模块>, conf, vars}`
2. **conf 必备键**（缺任一触发 exitScript）：`appid/开发比例[1280,720]/显示浮窗/卡屏检测/
   游戏模式/循环次数/无特征次数/timeout` 等，骨架见 engine/frame/jy_protocol.lua `baseSkeleton`；
   taps 必须带 `任务列表/任务列表模块` 空表
3. **日志回传**：单通道混流——`op=log` 帧（实时执行日志，"找到坐标：x,y"即特征命中）+
   `op=ok/warn` 回包；收帧循环过滤 log 帧等回包（参考模板 CloudWs.call）
4. **判定**：命中→"找到坐标"日志 + out 秒回（~0.3s）；未命中→无找到日志按循环次数退出；
   每个编译模块至少跑一次 pageTest 确认特征命中，失败模块回 Step 4 重新采样
5. 指令参数名：ps 域=`p` 串、fc 域=`color`、ft 域=`one+ct`、pic 域=`picName`（JY/Actions/ActionFramework.lua 注册表）

## 3. 失败处理规则

| 情况 | 处理 |
|------|------|
| 画面没变化 | 等待 1s，换元素内另一个点重试，最多 2 次 |
| 进入非预期界面 | 记录异常（anomalies）；找界面内关闭控件（X）退出回主界面重新规划；**禁 keyevent back**（可能触发退出游戏），确无关闭控件才 back 并验证未触发退出确认 |
| 连续失败 3 次 | 标记该子任务 failed，跳过或暂停，报告用户 |
| 检测到状态循环（A→B→A） | 跳出循环，报告异常 |
| 设备断开 | 尝试 `adb devices` 重查；仍失败则报告用户 |

## 4. 坐标规范

- 感知、操作阶段一律使用真实像素坐标
- 编译时由 coordinate.py 按九宫格锚点（1-9）换算为设计坐标
- 锚点自动判断：`.venv\Scripts\python.exe scripts/coordinate.py detect-anchor --x <center_x> --y <center_y> --resolution <w,h>`

## 5. 脚本输出约定

所有脚本 stdout 只输出 JSON：
- 成功：`{"status": "ok", "data": {...}, "meta": {...}}`
- 失败：`{"status": "error", "error": "<错误码>", "message": "..."}`
- 解析时先检查 status 字段，error 时读取 message 向用户说明

## 6. 新手引导 / 章节任务策略

识别信号：scene_label 含"引导/教程/章节/新手"；出现跳过按钮、手指高亮、遮罩气泡。

引导态行为：
1. **优先点"跳过"**（有跳过按钮绝不跟随引导）；无跳过 → 跟随手指高亮位置点击
2. **禁止采样稳定色点**（引导态画面一点就变，hit_rate 无意义）；特征采样只在主界面/稳定界面进行
3. 验证放宽：画面变化（phash>5）即算推进成功，不要求语义对齐 expected_scene
4. 引导弹窗照常记 anomaly；跨多轮引导每轮从主界面章节入口进入，录一段回主界面再进下一段
5. 成长型新手任务（七日/主线奖励，界面稳定）按普通任务正常采样录制，不受本节限制

模块拆分（详见 knowledge/新手引导与章节任务设计.md §6-§9）：
- **阶段性章节任务** → 按阶段拆子模块 + 路由中枢（进度变量分发），章节任务条目在任务列表锚点穿插；
  OCR 路由为阶段性专用：任务识别（OCR 写变量，认不清写 -1）+ 任务前往（inStr 关键词 → 运行后方法）
- **线性任务** → 主线扫描模块 + 分支动作子模块；OCR 路由不用，靠任务栏点击（自动寻路）+ 数值锚点退出
- TaskNode 命名直接用模块名（章节1_拜师 / 分支_拜访铁匠）；每到一个"阶段完成回主界面"点即结束当前子模块

任务模块 = 扫描式调度表（2026-09-13 定稿，纠错：禁止按录制顺序生成 A→B 步骤链）：
- 一个任务模块 = 优先级扫描表：每行 = 界面特征哨兵 → 动作（+可选跳子模块），
  每轮从第 1 行向下扫描，命中即执行再回第 1 行，直到 out/超时/变量条件退出
- 行序 = 优先级：弹窗清理行最前 → 任务推进行居中 → 兜底行最后；行尾放退出锚点
  （`{名,ff=nil,执行条件:变量阈值,out:true}`，如 OCR 攻击力>100000）
- 录制语义：同一任务模块遇到的所有界面状态+应对，去重后归并为该模块特征行
  （**不按 Transition 时间顺序串链**）；特征必须真实色点 hit_rate≥0.9，
  禁止 000000-101010 占位特征

弹窗与引导复用（阶段性/线性通用，详见设计文档 §8）：
- 双层弹窗库：一切弹窗特征去重追加进全局 `通用弹窗` 模块（`{名,ff=ps,out=true}`，
  跨模块跨任务复用）；业务行自动带 notFun="通用弹窗"；需跳子链的阶段专属弹窗放局部弹窗模块
- 引导 = "手指"哨兵行：guide-detect 产出全局手指特征，编译时每个业务模块首行自动注入
  `{"手指",5,ff="ty"}`；录制遇引导态只补手指特征、不录业务行（跳过按钮优先级不变）
- 界面退出：一律找界面内关闭控件（X）采样点击，**禁 keyevent back**（部分游戏会退出游戏），
  确无关闭控件才 back 且必须验证未触发退出确认框

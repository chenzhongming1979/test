# 新手引导与章节任务设计

> 依据真实脚本证据 + JY-Frame 框架惯例，定义 AutoScript 录制/编译时对新手阶段的处理设计。
> 证据来源：docs/analysis/batch_A~E（王城登录链、龙与王者"跳过新手向导"、龙迹之城新手任务、黎明之战"功能引导"、龙族霸业注释条目）

---

## 1. 职责分层（必须遵守，不得混淆）

| 模块 | 职责边界 | 不负责 |
|------|---------|--------|
| **进入游戏** | 保证从启动/登录状态到达**主界面**：启动弹窗清理、实名/公告、选区、断线重连 | **不处理引导内容**——录制中遇到引导界面立即停止，转交章节任务 |
| **章节任务** | 专职处理**新手引导/主线章节**推进：跟随引导、点跳过、领章节奖励，直到引导完成回主界面 | 不负责日常挂机任务 |

真实脚本证据：
- 王城登录链：`XX登录 → 进入游戏 → 隐藏弹窗/XX实名 → 是否在主界面 → 新手章节`（进入游戏只到主界面，"新手章节"是下一环）
- 龙与王者登录体系含独立模块：`跳过新手向导`、`新手引导前置`、`创建角色`
- 龙迹之城：成长型"新手任务"是 16 特征 3 子链的正式离线模块（升星/古宝/回收/强化）

## 2. 两类内容、两类对策

| 类型 | 特征 | 对策 |
|------|------|------|
| **强制引导/主线章节** | 遮罩+手指高亮、强线性、界面随进度变化、一次性 | 章节任务模块：推进型录制，**不采样色点**，编译为 run_once 一次性任务 |
| **成长型新手任务**（七日/主线奖励/升级建筑） | 界面稳定、按钮固定、跨天重复 | 普通任务模块：正常采样 + hit_rate 验证，与日常任务同等对待 |

## 3. 录制策略（AI 调度规则）

### 3.1 引导态识别信号
- `scene_label` 含：引导 / 教程 / 章节 / 新手
- 出现以下元素特征：**"跳过"按钮**、手指高亮图标、半透明遮罩层、引导对话气泡
- 点击任意位置后画面必然变化（引导强制推进）

### 3.2 引导态行为准则
1. **优先点"跳过"**（有跳过按钮绝不跟随引导）
2. 无跳过按钮 → 跟随手指高亮位置点击（视觉模型定位高亮元素）
3. **禁止采样稳定色点**：引导态画面一点就变，采样无意义；特征采样只允许在主界面/稳定界面进行
4. 验证标准放宽：画面变化（phash 距离>5）即算推进成功，不要求语义对齐 expected_scene
5. 引导弹窗照常记 anomaly（编译进通用弹窗）

### 3.3 推进型录制
- 引导可能跨多轮（章节间回主界面）：每轮从主界面"章节入口"进入，录一段，回主界面再进下一段
- 引导全部完成、回到主界面后：在 TaskNode 标记 `run_once: true`，目标场景写"主界面"（收口到锚点）
- 录制顺序建议：**先录章节任务（引导），再录日常任务**——引导不清完，日常界面不稳定

## 4. 编译映射（compile.py）

| 录制产物 | 编译行为 | 依据 |
|---------|---------|------|
| 进入游戏链 | 登录链模块 + 弹窗异常 → 通用弹窗 | M07 |
| 章节任务链 | **run_once 任务模块**（执行条件+变量赋值幂等对，二次挂机自动跳过） | M11 |
| 引导推进重复点击 | 同坐标 ±10px 多次 → ps_s + bigCount | M09 |
| 回主界面 | 收口到通用任务退出锚点 | M08 |
| 任务列表顺序 | 章节任务条目在前（一次性），日常任务在后 | M04 顺序保持 |

无需新增编译代码，全部由现有 M 规则覆盖；差异只在**录制策略**与**任务命名分层**。

## 5. 任务命名规范（沿用真实脚本惯例）

- 进入游戏 / XX登录：登录链
- 章节任务 / 新手引导：引导推进（run_once）
- 开始X：长流程起点（开始捐献、开始采集）
- X向导 / X弹窗：引导流/弹窗处理
- X检测 / X判断 / X识别：只读识别（isClick=false）

## 6. 任务模块拆分设计（阶段性 vs 线性）

### 6.1 阶段性章节任务 → 按阶段拆模块 + 锚点穿插调度

参考 .mq 真实设计（王城"章节任务"链、龙与王者锚点穿插、龙迹之城多容器）：

```
任务列表:
  章节任务        ← 锚点条目，每 5-6 条重复出现（每轮挂机检查推进）
  日常A
  章节任务        ← 再次出现
  日常B
  ...

taps.章节任务     ← 路由中枢：读进度变量 → 运行后方法 分发到当前阶段模块
taps.章节1_拜师   ← 每阶段一个子模块（出=进度标记+回主界面）
taps.章节2_打木人
taps.章节N_xxx
```

- **路由中枢模式**：章节任务主模块用执行条件/变量判断当前阶段，`运行后方法` 分发到对应阶段子模块（王城"前往检查"路由中枢实测 34 特征）
- **阶段门控**：每阶段子模块完成时 `变量赋值` 写进度，`执行条件` 门控（vars 章节>=N）
- **锚点穿插**：章节任务条目在任务列表中重复出现 = 每轮挂机都尝试推进；无进度时秒退（执行条件不满足）

### 6.2 线性任务 → 主线扫描模块 + 分支子模块

参考 .mq 真实设计（龙迹之城"新手任务"11 行扫描表）：

```
taps.主线_新手任务          ← 主线模块 = 优先级扫描表（不是步骤序列！）
taps.分支_背包 / 分支_英雄   ← 分支子模块：入口特征命中后 运行后方法 跳入，
taps.分支_转生 / 弹窗_任务     子模块内部也是扫描循环，out=true 回主线
```

- **主线模块是扫描表**：每行 = 界面特征哨兵 → 动作（+可选跳分支），每轮从第 1 行
  向下扫描，命中即执行再回第 1 行；线性推进感来自游戏自身寻路，脚本只负责
  反复点任务栏 + 清弹窗 + 做支线入口
- 退出锚点 = 变量条件行（如 OCR 攻击力 > 100000 → out），不是"走完流程"
- 同类分支（多个 NPC 拜访）用槽2 执行方法委托/参数化合并（R-D05）
- 判定标准：步骤可枚举且顺序固定 → 线性拆分；步骤随进度变化 → 阶段性拆分

### 6.3 AutoScript 录制对应

- AI 录制时按上述结构归组：每到一个"阶段完成回主界面"点就结束当前子模块
- TaskNode 命名直接用模块名（章节1_拜师 / 分支_拜访娄知县），编译器按任务名生成同名模块
- 进度变量记录在 run JSON 的 TaskNode（target_scene=阶段标记），编译为执行条件门控

## 7. 扫描式调度表语义（模块骨架，2026-09-13 定稿）

> 纠错：此前按"录制顺序"生成 A→B 线性步骤链是**错误**的。
> JY-Frame 的 taps 是**优先级扫描表**，模块内自循环，行序即优先级。

### 7.1 模块骨架

```
taps.<模块名>
  ["超时时间"] = N          ← 模块级超时（秒）
  ["强制休息"] = N          ← 每轮扫描间隔
  ["循环次数"] = N          ← 进入次数（可省）
  ["执行条件"] = [...]      ← 变量门控（不满足整模块跳过）
  [1] 手指哨兵行            ← 编译器自动注入（见 §8.2）
  [2..n] 业务特征行          ← 按优先级排列：弹窗清理最前、任务推进行居中
  [n+1] 兜底行              ← 最后（如"自动"挂机按钮）
  [退出行] {名,ff=nil,执行条件:变量阈值,out:true}   ← 退出锚点
```

### 7.2 行为语义

| 机制 | 语义 |
|------|------|
| 扫描顺序 | 每轮从第 1 行向下找首个命中行 → 执行 → 回第 1 行重来 |
| 行序 = 优先级 | 先清弹窗 → 再推进业务 → 最后兜底 |
| `out=true` | 子模块命中即回调用者；主模块命中即退出 |
| `isClick=false` | 纯检测哨兵（状态判断用，不点击） |
| `notFun` / `notTape` | 负向互斥：某模块/特征存在时本行不执行（防抢操作） |
| `ps_s` / `ps_w` | 点到特征消失 / 等待特征出现 |
| 变量锚点 | OCR 数值/时间戳变量：退出条件（攻击力>10万）、冷却（20min）、模式互斥 |

### 7.3 录制语义（compile.py 聚合规则）

- 同一任务模块录制过程中遇到的**所有界面状态+应对**，去重后归并为该模块的特征行
  （models.find_duplicate_state），**不按 Transition 时间顺序串链**
- 特征行必须真实色点（feature.py sample，hit_rate≥0.9），**禁止 000000-101010 占位特征**
- 采不到稳定色点的元素不进扫描表（改用 ft 找图行或 OCR 行）

## 8. 弹窗与引导复用架构（阶段性/线性任务通用）

### 8.1 双层弹窗库（参考巨兽战场 通用弹窗 + 章节任务弹窗）

| 层 | 模块 | 规则 |
|----|------|------|
| 全局 | `taps.通用弹窗` | 录制中遇到的**一切弹窗**特征去重后追加进来，跨模块/跨任务复用；行模式 `{名, ff=ps, out=true, p=关闭/确认钮特征}`；首行 = 手指 out（不抢引导活） |
| 局部 | `taps.<域>弹窗`（如 弹窗_任务） | 某业务阶段专属、且需要**跳子链**的弹窗（循环次数=10，部分行带 运行后方法） |

- 业务模块界面行自动带 `notFun="通用弹窗"`：弹窗开着不做业务
- 弹窗特征 = 共享资产：一次录制全网受益，二次录制同弹窗直接复用不重采

### 8.2 引导 = "手指"哨兵行（不是独立模块独占）

- guide-detect（OCR 跳过按钮 + CV 高亮/光圈/手指）产出全局"手指"特征（ft 全屏找图）
- **编译时每个业务模块首行自动注入** `{"手指",5,ff="ty"}`：任何界面出现引导态，
  当前模块先跟随引导推进，引导不在才做本模块业务（变体 `ty_ff="ft_s", bigCount=N`）
- 录制遇引导态：只补手指特征，**不录业务行**（业务特征等引导过完、界面稳定后再采）
- 跳过按钮优先级不变：有"跳过"先点跳过（guide-detect 已内置该优先级）

### 8.3 OCR 路由 = 阶段性任务专用（线性任务不用）

- `taps.任务识别`：OCR 读任务文本 → 写进度变量，**认不清写 -1**（防乱点）
- `taps.任务前往` 路由模块：每行 `执行条件 = 当前任务文本 inStr 关键词 → 运行后方法 跳子模块`，
  关键词用 `"or"` 多候选兜底（OCR 局部错字也能命中）
- 线性任务不靠 OCR 路由：靠任务栏点击（游戏自动寻路）+ 数值锚点退出

## 9. 界面退出规范（2026-09-13 用户规则：禁 back）

> **不要通过点击系统返回键（keyevent back）返回主界面**——部分游戏按返回会弹
> "退出游戏"确认框甚至直接退出。

1. 退出任何界面（弹窗/子界面/功能页）**一律找界面内关闭控件**（X / 关闭 / 返回图标）
   采样点击，验证回到预期界面
2. 只有界面上确实**无任何关闭控件**时才允许 back，且必须 postclick 验证：
   - 检测画面是否出现"退出游戏 / 确定退出 / 再按一次退出"等关键词 → 出现立即点取消并记 anomaly
   - back 后 scene_label 变为"桌面/launcher" → 说明游戏被退出，记严重 anomaly 并重启游戏链
3. 编译映射：业务模块的"退出"行 = 关闭钮特征行（ps，out=true）；不生成 keyevent back

## 10. 线性任务执行过程检测机制（2026-09-13 定稿）

> 线性任务每次点击后进入"执行过程"：打怪（有 X/Y 数量）、找 NPC 对话（有对话框）、
> 点击触发弹窗。三类机制检测代码已实现于 verify.py，编译为标准模块行。

### 10.1 三类检测（verify.py 已实现，postclick 自动输出 + 独立子命令）

| 检测 | 函数/子命令 | 输入样式 | 输出 | 录制时用途 |
|------|------------|---------|------|-----------|
| 数量进度 | `detect_quest_progress` / `quest-progress` | 任务栏 "击败野狼 3/5"（兼容全角／） | `{cur, total, done, center}` | 判断打怪/采集任务是否完成（循环锚点） |
| 对话框 | `detect_dialog` / `dialog-detect` | 底部 1/3 屏"继续/完成/离开/接受/交付"按钮 | `{is_dialog, buttons, click_hint}` | NPC 对话推进：重复点 click_hint 直到按钮消失 |
| 弹窗分类 | `classify_popup` / `popup-classify` | reward(领奖)/confirm(确认)/dismiss(关闭) 关键词 | `{category, click_hint, hits}` | 点击后弹窗直接按分类处理：reward→点领取、confirm→点确定、dismiss→点关闭；同时采样入库通用弹窗库 |

优先级约定：引导（guide-detect 的跳过/高亮）> 弹窗分类 > 对话 > 业务推进；
postclick 的 result 中 popup/dialog/quest 三字段与 mask/guide 并列输出。

### 10.2 编译模块模板（三类机制 → 扫描表行）

打怪/采集任务（数量锚点，参考巨兽战场 ocrCompare + 龙迹血量哨兵）：

```
taps.分支_击败野狼 = {
  {"手指",5,ff="ty"},
  {"数量识别",5,ff="ocr",ocrParams=任务栏区,ocrWrite=vars.野狼数},   -- 数量检测编译
  {"任务栏",5,ff="ps",p=任务栏特征,notFun="通用弹窗"},               -- 寻路/自动打
  {"战斗中",5,ff="ps",isClick=false,wait=0,p=血条特征},             -- 打完等回
  {"数量已满",5,ff=nil,执行条件=野狼数>=5,out=true,运行后方法="交付"}, -- done→交任务
}
```

NPC 对话任务（对话框检测编译）：

```
taps.分支_拜访XX = {
  {"手指",5,ff="ty"},
  {"对话继续",5,ff="ps_s",bigCount=N,p=继续按钮特征},   -- 循环点对话直到按钮消失
  {"交付",5,ff="ps",p=交付按钮特征,out=true},
}
```

点击触发弹窗：录制时 classify_popup 给出 category → 对应处理（reward/confirm/dismiss）
采样后追加进通用弹窗库；业务模块行自动 notFun="通用弹窗"（§8.1 已定）。

### 10.3 录制流程增量

1. 点击后 postclick：新增读 `popup`（分类处理）、`dialog`（有则循环点对话并采样按钮特征）、
   `quest`（打怪/采集任务记录 X/Y 文本与区域 → 写入 TaskNode 作为数量锚点）
2. 打怪/采集任务：录制时用 quest.done 判断任务完成，数量未满不交任务；任务栏区域
   （task_region）一并记录，编译生成 ocr 数量锚点行
3. NPC 对话：detect_dialog 命中后连续点击直到 is_dialog=false，按钮位置采样为
   ps_s + bigCount=N 行

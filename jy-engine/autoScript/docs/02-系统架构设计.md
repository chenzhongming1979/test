## 1. 架构概述

### 1.1 定位

AutoScript 是一套**基于 Trae AI IDE 的脚本生成工具套装**，由 Python CLI 脚本 + Trae 规则/角色定义组成。Trae 的 AI 助手作为调度大脑，按规则自主调用脚本完成全流程。

**不是**独立运行的 Agent 程序，**不依赖** MCP 或独立 Agent 框架。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 纯脚本调用 | AI 直接调 `python scripts/xxx.py`，不用 MCP Server |
| 文件自包含 | 每个脚本 = 核心函数 + CLI 入口，可 import 可命令行执行 |
| 函数与 CLI 解耦 | 核心函数不依赖 argparse，迁移时直接 import |
| 轻量存储 | 用 JSON 文件存状态机，不引入数据库 |
| 迁移冗余 | `trae/` 目录可整体替换为 `aistruct/`，核心脚本零改动 |

## 4. 核心循环

AI 按 `trae/rules.md` 调度脚本，每轮循环对应脚本中一行特征：

```
┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐
│①截图│───▶│②分析│───▶│③取色│───▶│④规划│───▶│⑤执行│───▶│⑥验证│
└─────┘    └─────┘    └─────┘    └─────┘    └─────┘    └─────┘
   ▲                                                         │
   │              成功→记录转移→继续                           │
   └─────────────────────────────────────────────────────────┘
                       │
                       ▼ 任务完成
                  ┌─────────┐
                  │⑦编译输出 │
                  └─────────┘
```

| 步骤 | 脚本 | AI 做什么 |
|------|------|----------|
| ① 截图 | `adb.py screenshot` | 调用脚本，获取截图路径 |
| ② 分析 | `analyze.py --image` | 调用脚本，获取界面元素 JSON |
| ③ 取色 | `feature.py sample` | 对目标元素采样稳定色点 |
| ④ 规划 | AI 推理 | 基于界面+目标，决定点哪/滑哪/等多久 |
| ⑤ 执行 | `adb.py click/swipe` | 调用脚本执行操作 |
| ⑥ 验证 | `feature.py compare` + AI 判断 | 画面变化检测 + 语义验证 |
| ⑦ 编译 | `compile.py --run-id` | 状态机→taps 脚本 |

## 5. 技术选型

| 层次 | 技术 | 选型理由 |
|------|------|---------|
| AI 宿主 | Trae AI IDE | 用户已使用，AI 助手直接调度脚本 |
| 语言 | Python 3.11+ | 图像处理/ADB/LLM 库成熟 |
| 设备连接 | ADB (subprocess) | 通用、稳定，兼容所有模拟器和真机 |
| 图像处理 | Pillow + numpy + opencv | 色点采样、感知哈希、图像对比 |
| OCR | RapidOCR | 离线、轻量、中文识别好 |
| 视觉理解 | Trae 已配置的 LLM | analyze.py 封装调用，复用 Trae 配置 |
| 脚本模板 | jinja2 | 多平台输出，模板与逻辑分离 |
| 状态存储 | JSON 文件 | 轻量，Trae 套装阶段不引入数据库 |
| 规则/角色 | Markdown（trae/） | Trae 原生支持，零额外依赖 |

**明确不选**：
- ❌ MCP Server：纯脚本调用更轻量，AI 直接调命令行即可
- ❌ 独立 Agent 框架（LangGraph 等）：Trae AI 本身就是调度器
- ❌ SQLite/数据库：JSON 文件足够，减少依赖
- ❌ 独立 UI：复用 Trae 界面

## 7. 架构决策记录（ADR）

### ADR-001：选择 Trae 套装方案，不独立开发

**决策**：以 Trae AI IDE 为宿主，用脚本套装方式实现，不开发独立 Agent 程序。

**理由**：
- Trae AI 本身就是成熟的调度器，不用自建 Agent 循环
- 纯脚本方式开发量最小（约为独立开发的 40%）
- 用户已在使用 Trae，零学习成本
- 预留了迁移冗余，以后可迁到 AIStruct

**后果**：
- 依赖 Trae 环境，不能脱离 Trae 独立运行
- AI 调度逻辑写在 rules.md 里，不是代码

### ADR-002：纯脚本调用，不用 MCP

**决策**：AI 通过命令行直接调用 `python scripts/xxx.py`，不封装 MCP Server。

**理由**：
- MCP 需要常驻 Server、协议封装，过度设计
- 纯 CLI 调用最简单，AI 生成命令即可执行
- 每个脚本输出 JSON，AI 解析后继续决策
- AIStruct 也有 `coding_cli_exec` 节点，迁移后照样调命令行

**后果**：
- 每次调用起一个 Python 进程（性能可接受，单步操作秒级）
- 无状态保持（ADB 连接每次重连，或用 adb server 常驻）

### ADR-003：src 合并到 scripts，文件自包含

**决策**：不区分 src/（核心）和 scripts/（入口），合并为 scripts/，每个文件内部核心函数与 CLI 入口分离。

**理由**：
- 目录更简洁
- 每个文件 `if __name__ == "__main__"` 处理 CLI，上方定义核心函数
- 迁移时 import 核心函数即可，不用改代码

**后果**：
- 文件稍大（函数+CLI 在同一文件）
- 核心函数必须保持无副作用、可独立 import

### ADR-004：JSON 文件存储状态机，不引入数据库

**决策**：运行时状态机用 JSON 文件存在 `state/` 目录，不使用 SQLite。

**理由**：
- Trae 套装阶段数据量小（一次任务几十个状态）
- JSON 可读、可调试、AI 可直接查看
- 减少依赖，环境更简单

**后果**：
- 不支持并发写入（单任务串行，无影响）
- 迁移到 AIStruct 时可换 memory_manager

### ADR-005：锚点换算采用九宫格系统

**决策**：坐标换算采用九宫格锚点系统（1-9），根据控件在屏幕中的位置自动判断锚点，实现全分辨率适配。

**锚点定义**：
```
1=左上  2=上中  3=右上
4=左中  5=中心  6=右中
7=左下  8=下中  9=右下
```

**换算逻辑**：锚点所在的边/角作为"固定边"，坐标从固定边往内算，而非统一从左上角缩放。例如锚点 3（右上）：x 从右边缘计算，y 从上边缘计算。

**理由**：
- JY-Frame 框架原生采用此机制，全分辨率适配的核心
- 底部菜单（锚点 8）、右上角关闭按钮（锚点 3）等在不同分辨率下位置保持合理
- 公式已确认，无需逆向源码

**后果**：
- coordinate.py 实现 9 种锚点的双向换算
- 每个特征行需记录对应锚点，编译时写入脚本
- 自动判断锚点：控件中心落在哪个九宫格就用哪个锚点

## 8. 迁移路径（Trae → AIStruct）

```
当前（Trae）                    迁移后（AIStruct）
─────────────                  ─────────────────
trae/soul.md          ──替换──▶  aistruct/SKILL.md（角色定义）
trae/rules.md         ──替换──▶  aistruct/ 流程 DAG（编排）
scripts/*.py          ──复用──▶  scripts/*.py（零改动）
templates/            ──复用──▶  templates/
config/               ──复用──▶  config/
knowledge/            ──复用──▶  knowledge/
AI 调度（rules驱动）   ──替换──▶  AIStruct pipeline_executor
```

**迁移工作量**：只需重写 `trae/` 目录为 AIStruct Skill + 流程 DAG，核心脚本、模板、配置全部复用。预计 1-2 周。

## 9. 与 JY-Frame 框架的关系

AutoScript 是 JY-Frame 框架的**脚本生成工具**，输出的脚本直接兼容 JY-Frame：

| AutoScript 概念 | JY-Frame 概念 |
|----------------|--------------|
| 界面状态 | 任务模块 `taps.状态名` |
| 稳定色点 | `ff="ps", p="x\|y\|color-tol,..."` |
| 状态转移 | `运行后方法="下一模块"` / `out=true` |
| 循环操作 | `ff="ps_s"` |
| 等待界面 | `ff="ps_w", waitOut=...` |
| 操作验证 | 防卡死机制 |

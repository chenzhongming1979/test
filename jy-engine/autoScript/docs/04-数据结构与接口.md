# 数据结构与接口定义

> 版本：v2.0（Trae 套装方案）  
> 日期：2026-09-11  
> 状态：初稿

---

## 1. 概述

AutoScript 采用 **CLI + JSON** 作为模块间接口。Trae AI 通过命令行调用脚本，脚本输出 JSON，AI 解析后继续决策。状态机数据用 JSON 文件存储。

本文档定义：
- 核心数据结构（JSON Schema）
- 各脚本的 CLI 接口（命令、参数、输出）
- 状态文件格式
- 配置文件格式

---

## 2. 核心数据结构

### 2.1 UIElement — 界面元素

```json
{
  "id": "elem_001",
  "type": "button",
  "text": "副本",
  "bbox": [300, 1100, 420, 1200],
  "center": [360, 1150],
  "confidence": 0.95,
  "is_primary": true,
  "stable_points": [
    {"x": 324, "y": 1150, "color": "837C75", "tolerance": "101010"}
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| id | string | ✓ | 元素唯一ID |
| type | string | ✓ | button/icon/list_item/input/tab/text |
| text | string | ✓ | 文字内容或描述 |
| bbox | array[4] | ✓ | [x1,y1,x2,y2] 真实像素 |
| center | array[2] | ✓ | [x,y] 点击中心点 |
| confidence | number | ✓ | 识别置信度 0-1 |
| is_primary | boolean | ✗ | 是否主要操作按钮 |
| stable_points | array | ✗ | 稳定色点列表 |

### 2.2 ScreenState — 界面状态

```json
{
  "state_id": 0,
  "scene_label": "主界面",
  "description": "游戏主界面",
  "elements": [UIElement, ...],
  "texts": [{"text": "等级50", "bbox": [50,30,150,60]}],
  "phash": "a1b2c3d4e5f60718",
  "screenshot": "screenshots/shot_001.png",
  "resolution": [720, 1280],
  "timestamp": 1234567890.123
}
```

### 2.3 Action — 操作动作

```json
{
  "type": "click",
  "coord": [360, 1150],
  "swipe_from": null,
  "swipe_to": null,
  "duration": 0,
  "input_text": "",
  "wait_seconds": 0,
  "expected_scene": "副本选择",
  "reason": "点击副本按钮进入副本选择界面"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| type | string | click/swipe/long_press/input_text/wait/back/home |
| coord | array[2]? | 点击坐标（click 时） |
| swipe_from/to | array[2]? | 滑动起终点（swipe 时） |
| duration | number | 滑动时长 ms |
| input_text | string | 输入文字（input_text 时） |
| wait_seconds | number | 等待秒数（wait 时） |
| expected_scene | string | 操作后期望界面 |
| reason | string | 决策理由 |

### 2.4 Feature — 特征行

```json
{
  "name": "副本入口",
  "ff": "ps",
  "ps_param": "324|1207|837c75-101010,357|1205|f5e7ce-101010",
  "degree": 0.9,
  "priority": 5,
  "out": false,
  "next_method": "副本选择",
  "is_click": true,
  "wait": 0,
  "anchor": 3,
  "verified": true,
  "hit_rate": 1.0
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| name | string | ✓ | 特征描述 |
| ff | string | ✓ | 动作指令 ID（ps/ps_s/ps_w/ft/...） |
| ps_param | string | ✓ | p 参数：`x\|y\|颜色-偏色,...` |
| degree | number | ✓ | 相似度 0-1 |
| priority | number | ✓ | 优先级 |
| out | boolean | ✗ | 是否出口特征 |
| next_method | string | ✗ | 匹配后跳转模块 |
| is_click | boolean | ✗ | 是否点击（默认 true） |
| wait | number | ✗ | 等待 ms |
| **anchor** | **number** | **✓** | **九宫格锚点 1-9，编译时用于坐标换算** |
| verified | boolean | ✗ | 是否经过多帧验证 |
| hit_rate | number | ✗ | 验证匹配率 |

### 2.5 Transition — 状态转移

```json
{
  "from_state": 0,
  "to_state": 1,
  "action": Action,
  "feature": Feature,
  "success": true,
  "duration_ms": 1200,
  "timestamp": 1234567890.123
}
```

### 2.6 TaskNode — 任务节点

```json
{
  "task_id": 0,
  "name": "进入副本",
  "target_scene": "副本选择",
  "is_repeatable": false,
  "repeat_count": 1,
  "current_repeat": 0,
  "status": "completed",
  "order": 0
}
```

## 3. 通用响应格式

所有脚本统一输出格式：

### 3.1 成功

```json
{
  "status": "ok",
  "data": { ... },
  "meta": {
    "script": "adb.py",
    "command": "screenshot",
    "timestamp": 1234567890.123,
    "duration_ms": 123
  }
}
```

### 3.2 失败

```json
{
  "status": "error",
  "error": "DEVICE_NOT_FOUND",
  "message": "设备 emulator-5554 未连接",
  "meta": { ... }
}
```

### 3.3 退出码

| 退出码 | 含义 |
|--------|------|
| 0 | 成功 |
| 1 | 通用错误 |
| 2 | 参数错误 |
| 3 | 设备错误 |
| 4 | 外部依赖错误（LLM/OCR） |

## 4. CLI 接口规范

### 4.1 adb.py

| 命令 | 参数 | 输出 data |
|------|------|----------|
| `doctor` | - | `{checks: [...], summary: {passed, failed, warnings}}` |
| `devices` | - | `{devices: [{serial, state, model}]}` |
| `screenshot` | `--device`, `--output` | `{path, resolution, size_bytes}` |
| `click` | `--device`, `--x`, `--y` | `{success, x, y}` |
| `swipe` | `--device`, `--x1`, `--y1`, `--x2`, `--y2`, `--duration` | `{success}` |
| `input` | `--device`, `--text` | `{success}` |
| `keyevent` | `--device`, `--key`(back/home) | `{success}` |
| `resolution` | `--device` | `{width, height, density}` |

### 4.2 analyze.py

| 命令 | 参数 | 输出 data |
|------|------|----------|
| （默认） | `--image`, `--ocr-only`?, `--vision-model`?, `--output`? | `ScreenState` |

### 4.3 feature.py

| 命令 | 参数 | 输出 data |
|------|------|----------|
| `sample` | `--image`, `--bbox`(x1,y1,x2,y2), `--count`? | `{points, ps_param, hit_rate}` |
| `phash` | `--image` | `{phash}` |
| `compare` | `--before`, `--after` | `{phash_distance, changed, similarity, change_regions}` |
| `verify` | `--image`, `--points`(JSON) | `{hit_rate, matched, total}` |

### 4.4 coordinate.py

| 命令 | 参数 | 输出 data |
|------|------|----------|
| `convert` | `--x`, `--y`, `--from`(real/design), `--to`(real/design), `--resolution`(w,h), `--anchor`(1-9) | `{x, y, from, to, anchor}` |
| `detect-anchor` | `--x`(center_x), `--y`(center_y), `--resolution`(w,h) | `{anchor: 1-9, region: "左上|上中|..."}` |
| `detect` | `--device` | `{width, height, density}` |
| `verify` | `--device`, `--test-point`(x,y), `--anchor`(1-9) | `{real_point, design_point, framework_point, match}` |

### 4.5 compile.py

| 命令 | 参数 | 输出 data |
|------|------|----------|
| （默认） | `--run-id`, `--platform`(lua/vb/js/go), `--output` | `{output_path, modules_count, features_count}` |
| `list-runs` | - | `{runs: [{run_id, goal, timestamp, states_count}]}` |
| `inspect` | `--run-id` | `{run_id, goal, states, transitions, task_tree}` |

## 5. 状态文件格式

运行时状态机存在 `state/run_<timestamp>.json`：

```json
{
  "run_id": "run_20260911_143000",
  "goal": "自动刷火副本，刷完回城",
  "device_id": "emulator-5554",
  "resolution": [720, 1280],
  "design_resolution": [720, 1280],
  "anchor_type": "top_left",
  "start_time": 1234567890.123,
  "end_time": null,
  "status": "running",
  "states": [ScreenState, ...],
  "transitions": [Transition, ...],
  "task_tree": [TaskNode, ...],
  "anomalies": [
    {
      "state_id": 5,
      "type": "popup",
      "trigger_action": "click",
      "handled": true,
      "handle_method": "back",
      "screenshot": "screenshots/anomaly_001.png"
    }
  ]
}
```

### 5.1 状态去重

新状态入库前：
1. 计算 phash
2. 查找已有状态中 phash 汉明距离 < 5 且 scene_label 相同的
3. 命中则复用 state_id，不新增
4. 未命中则分配新 state_id

## 6. 配置文件格式

### 6.1 config/devices.yaml

```yaml
devices:
  - name: "雷电模拟器"
    serial: "emulator-5554"
    type: "emulator"
    design_resolution: [720, 1280]
    # 锚点自动判断：根据控件中心在九宫格中的位置决定（1-9）
    # 如需强制指定锚点，取消注释下面这行
    # force_anchor: null
  - name: "测试真机"
    serial: "1234567890ABCDEF"
    type: "device"
    design_resolution: [720, 1280]

default_device: "雷电模拟器"
```

```yaml
vision:
  provider: "doubao"
  api_key: "${DOUBAO_API_KEY}"

  model_dir: "./models/ocr"

  point_count: 3
  variance_threshold: 50
  contrast_threshold: 30
  min_tolerance: "101010"
  max_tolerance: "303030"
  verify_frames: 3

  default_platform: "lua"

verifier:
  phash_diff_threshold: 5

  wait_stable_timeout_ms: 3000
```

## 9. 接口版本管理

- 所有 JSON 输出包含 `meta.api_version`（当前 "1.0"）
- 破坏性变更（字段删除/重命名）升级大版本
- 新增字段升级小版本
- AI 调用时不指定版本，始终用最新

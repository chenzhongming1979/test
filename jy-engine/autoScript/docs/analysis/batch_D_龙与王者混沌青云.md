### 1.1 本批文件的统一骨架（与 doc 02 的 Lua 版的对应关系）

四个主文件都是同一骨架（按键版方言）：

```vb
Import "runFun.mql" : Import "HJG.lua" : Import "change.lua"   // 框架+工具
Dim conf() : Dim vars() : Dim taps()                            // 对应 Lua 的 conf/vars/taps
conf["开发比例"] = Array(720,1280) : conf["outTime"] = 60*10 : conf["循环次数"] = 20 ...
Function getTaps()                     // 所有 taps 模块在此定义
    taps["进入游戏"] = Array()          // ① 模块声明
    taps["进入游戏"]["name"] = "进入游戏" // ② 自描述（新版标配）
    taps["进入游戏"]["超时时间"] = 60*20 // ③ 模块级配置（对应 doc16 的模块属性）
    Dim 进入游戏 = taps["进入游戏"]      // ④ 局部别名（本批独有写法）
    进入游戏(UBOUND(进入游戏)+1) = {...} // ⑤ 特征行追加（等价 taps["X"][N]={...}）
    taps["任务列表"] = Array()
    Dim 任务列表 = taps["任务列表"]

    taps = change.freemInit(Array(720,1280), Array(GetScreenX(),GetScreenY()), Null, taps)  // ⑥ 分辨率适配注册

```

关键框架事实（来自 jy-frame 源码，文档未写）：
- `任务参数设置(启动方法, 执行方法, 执行模式, 执行间隔时间, 进入任务超时时间, 是否有对应设置, 执行次数, UIID, 任务执行前操作)`（FrameUtils.lua:656）——任务列表条目第 9 槽的**权威语义**：
  - 槽1 启动方法：0=主界面启动(找色) / 1=指定方法启动 / 2=主界面启动(直接点击)
  - 槽2 执行方法：执行指定任务模块（复用实现）
  - 槽3 执行模式：0=不限制 / 1=每天一次 / 2=每周一次 / 3=每月一次
  - 槽4 执行间隔时间：-1=不限制，否则秒数（如 `60*60*3`）
  - 槽5 进入任务超时时间（标注弃用，但脚本仍填 `20*1000` 等）
  - 槽6 是否有对应设置（bool）
  - 槽7 执行次数；槽8 UIID；槽9 任务执行前操作=任务模块名（如"展开功能"、"滑动4"）
- FrameRun.lua:67-72：任务调试时若 `任务参数` 是裸数组，会自动经 `jy_frame.任务参数设置()` 重建 —— 证实槽位顺序。
- 龙于王者/混沌起源部分条目直接写 `array(0,null,0,...)` 裸数组（不走 helper），运行时同样被重建。

#### 2.1.1 主线锚点循环（调度结构核心）

`打野`/`是否在城外` 每 5~6 条任务重复插入一次，形成"城内任务批 → 出城打野 → 回城 → 下一批"的节奏。这是**任务列表层的调度模式**，不依赖任何代码：

```
…城内批(升级主城/收集资源/英雄/VIP/礼包) → 打野 → 是否在城外 → 联盟医院/膜拜/背包/联盟…
```

模块链（所有锚点共享）：

```
打野 → 等级选择 / 野怪识别 → 野怪识别 → 等级识别 / 出征 / ⇢notFun 打怪检测
是否在城外 → 是否在城内 / ⇢notFun 通用任务退出
是否在城内 → ⇢notFun 通用任务退出
通用任务退出 → 闯关退出 / ⇢notFun 通用弹窗（框架约定模块，doc27）
```

#### 2.1.2 建筑升级族（3 条入口 + 1 条收尾共用实现）

```
升级主城 ─notFun→ 升级主城弹窗 ─→ 升级建筑/建造建筑/加速界面/加入联盟/购买队列
```

#### 2.1.4 消消乐闯关链（深度剖析①）

## 3 模块拆分经验

### 3.1 命名规律（跨 4 文件稳定）

| 后缀/模式 | 语义 | 实例 |
|---|---|---|
| 动宾结构 | 一个业务动作 = 一个模块 | 升级主城、收集资源、爆骑兵、升起女神 |
| `X界面/X主界面` | 界面状态锚点 | 主城主界面、消消乐界面、账号注册界面 |
| `X退出` | 该系统的收尾退出 | 竞技退出、试炼退出、紫矿退出、联盟仓库退出 |
| `通用X退出` | 跨系统复用退出 | 通用任务退出、活动退出、联盟通用退出、研究通用退出、属性升级通用退出 |
| `X检测/X判断/X识别/X检查` | 只读识别（isClick=false 为主） | 副本检测、引导检测、队列识别、治疗检查、BOOS识别 |

| 数字分档 | 数值梯度 | 升120/130/140/150/160、紫矿1、使用1000、补齐500K |

### 3.2 拆分粒度

- **一个 UI 状态 = 一个模块**（龙与王者2 紫矿族拆出 8 个模块；青云决向导家族一个向导一个模块）。特征行中位数 5~8 行/模块；>20 行的模块（弹窗检测 11、进入游戏 31/13、通用弹窗 26/18）都是"兜底多弹窗"性质，新版在主动拆薄（通用弹窗 26→18，进入游戏 31→13）。
- **识别与动作分离**：`X检测`（isClick=false，只判断）→ `运行后方法` → 动作模块；`notTape/tape` 把"找不到时点哪"也拆成一行。
- **入口-实现分层**：任务列表条目（触发特征+调度参数）→ 入口模块（识别界面）→ 实现模块（槽2 执行方法或运行后方法委托）→ 收尾模块（X退出）。

### 3.3 复用模式

1. **执行方法委托**（任务参数槽2）：升级铁匠铺/市场/大使馆→`普通升级`；步兵/骑兵/弓兵/器械→`造兵`；神秘商店/试炼→`招募`；陷阱→`造兵通用`。同一实现、多入口、各自触发特征与限频。
2. **退出方法族**：模块配置 `退出方法` 共 136 处（44+42+17+33），`通用任务退出` 占 52 处；其余为领域收尾（活动退出 29 处、属性升级退出/通用退出 21 处）。框架每任务退出后还会自动跑 `通用任务退出`（doc27），领域退出负责"把界面退回任务起点"。
3. **notFun 兜底链**：`X ⇢notFun→ 通用任务退出 ⇢notFun→ 通用弹窗 → 返回` 是所有任务的最后防线（doc27 通用任务退出机制的脚本侧体现）。
4. **通用特征库**：旧版 `ty_n:"出城/回城/主界面/每日必做"`（133 处）共享锚点特征；新版改为 `特殊特征` 字符串键特征表 + 每行自写 `r/picName`。
5. **前置导航模块**：任务参数槽9（任务执行前操作）复用 `展开功能/展开奖励/滑动3/滑动4/装备守护小精灵/联盟采集仓库1` —— 把"进入任务前必须点开的 UI"抽成公共模块。
6. **截图至内存**：8 处（升级主城弹窗、关卡选择等密集找图模块）对应 doc16 截图至内存优化。

## 4 可复用规则清单（面向编译器映射）

- **R-D01 模块声明三件套**：`taps["X"]=Array()` + `taps["X"]["name"]="X"` + `Dim 别名 = taps["X"]`；特征行一律 `别名(UBOUND(别名)+1)={...}` 追加。编译器可把三件套折叠为一个"模块声明"，特征行数组即模块体（与 doc02 的 `taps["X"][N]=` 语义等价）。
- **R-D02 任务列表条目形态**：`{"任务名", 优先级, "ff":触发指令, "任务参数":9槽, 触发特征参数(p/r/picName/ocrParams/z/clickRange), "执行条件", "wait/waitOut", "变量赋值"}`。条目本身就是"带调度参数的特征行"，任务名同时是模块名。
- **R-D03 任务参数 9 槽固定语义**：`(启动方法, 执行方法, 执行模式, 执行间隔时间, 进入任务超时时间, 是否有对应设置, 执行次数, UIID, 任务执行前操作)`（FrameUtils.lua:656）。编译器应映射为结构化调度配置而非保留裸数组。
- **R-D04 调度频率映射**：槽3=1/2 每日/每周 + 槽4 间隔秒数（60*60*3~60*60*8 常见）→ 编译器的任务频率原语；槽5 超时虽标注弃用，实际脚本仍填 `10*1000~30*1000`，应映射为"进入任务超时"而非忽略。
- **R-D05 执行方法委托（槽2）**：多入口共享实现时，入口条目只写触发特征+槽2；编译器应生成"入口→实现"的调用边，而不是复制实现体。
- **R-D06 任务执行前操作（槽9）**：进入任务前先跑一个公共模块（展开功能/滑动N/装备小精灵）。编译器映射为任务前置钩子。
- **R-D07 优先级惯例**：常规任务=5；收尾/低频=2~3；信息刷新=4；调试/强插=8。默认 5，无需显式。
- **R-D08 链式跳转三元组**：`out:true+运行后方法`（找到即跳）、`isClick:false+运行后方法`（识别即跳不点击）、`notOut:true+notFun`（找不到才算命中/兜底）。这是状态机边，编译器应生成显式转移。
- **R-D09 兜底三明治**：业务模块 ⇢notFun→ 通用任务退出 ⇢notFun→ 通用弹窗（循环次数=1）→ 返回。编译器为每个任务自动补齐该兜底链（doc27 框架约定）。
- **R-D10 领域退出方法**：每个子系统配 `X退出`/`通用X退出`，模块配置 `退出方法` 指向之；框架层再跑通用任务退出。两层退出语义不同：领域退出=回任务起点，通用退出=回主界面。
- **R-D11 状态变量协议**：写 `变量赋值(true,Array(Array("任务变量",K,V,"s")))`；读 `执行条件=array(array(1,"任务变量",K,"==",V))`。跨模块状态一律走 `任务变量`（账号生命周期，doc03），登录态走 `状态变量`。
- **R-D12 环状互跳必须限次**：模块级 `循环次数>1`（加速界面=5、闯关=5）或 `超时时间`，配合 outCode/notFun 出口；编译器检测模块互跳环时自动注入限次。
- **R-D13 锚点穿插调度**：任务列表按"批 + 锚点任务（打野/是否在城外）+ 批"排列，用重复条目表达节奏；编译器应保留任务列表顺序语义，不得按名称去重。
- **R-D14 同名多条件条目**：青云决"转职任务"双等级区间 = 同名条目 × 不同执行条件。映射为"一个任务 + 条件分支表"。
- **R-D15 动作随机化三件套**：`clickRange`（范围内随机点击，797 处）、`offset`（特征偏移）、`tape`（定点）。编译器应将 clickRange 识别为反检测原语。
- **R-D16 多候选图/多点比色**：`picName` 用 `|` 拼接多张候选图（增益.png|增益3.png|增益2.png）；`p` 用 `array(array(x,y,color),…)` 多点同时比色。编译器需支持候选集与点集两类输入。
- **R-D17 OCR 找字触发**：`fs_c` + `ocrParams(x1,y1,x2,y2,色差,模糊度,"文本")` + `offset(-10,60,-1)` 用于 OCR 文本按钮（神秘商店/战旗/挑战/0元购）。
- **R-D18 通用特征锚点**：旧版 `ty_n`（出城/回城/主界面）= 界面合法性前置检查；新版改用 `特殊特征` 字符串键特征表（taps["特殊特征"]["红"]）。编译器可提供"命名特征常量表"。
- **R-D19 防卡死配置**：混沌起源 `计时任务={60*10,"向前移动"}`；新版弹窗检测扩到 11 行特征、检测线程 12 行。编译器应为长任务默认生成计时任务/卡屏处理。
- **R-D20 分辨率适配**：`change.freemInit(Array(720,1280), Array(GetScreenX(),GetScreenY()), Null, taps)` + `Rect(x,y,w-x,h-y)` 相对区域 + `conf["driveWidth/Height"]`。坐标常量按 720×1280 设计，运行期缩放。
- **R-D21 迷你改版模式**：改版脚本只重写 `getTaps()/getTaps2()` 并保留框架 Import；编译器应支持"模块级差异补丁"产物（对应 QYJ_NEW/HD_NEW）。
- **R-D22 UI 配置读取**：`ReadUIConfig("键")` 直接出现在执行条件/执行条件表达式（`ReadUIConfig("开罩模式") = 0`），也可 `array(ReadUIConfig("治疗")=true, array(...))` 混合 AND。UI 开关是条件的一等公民。

## 5 坑与反例

1. **键名笔误 `"wait:"`**：龙与王者2 关卡选择 3 行特征写成 `{"无行动力",5,"ff":"fc_c","wait:":0,...}`（冒号进键名），框架读不到 wait —— 静默失效。编译器必须校验键名白名单（行 3524-3526）。
2. **`任务界面` 空配置**：旧版 55 处 `taps["X"]["任务界面"]=Array(Array(...))` 传空数组，条件永真无意义；新版全部删除。空 Array 条件应视为无效配置并在编译期报 warning。
3. **超时形同虚设**：龙于王者 `90*60*60`（90 小时）超时配置 —— 数值合法性检查（>24h 警告）。
4. **同名任务条目依赖框架遍历顺序**：FrameRun.lua:55-58 `for … if value[1]==taskName then task=value`，同名条目**取最后一条**。青云决双区间转职任务恰好条件互斥无碍；若条件重叠会静默丢任务。
5. **`taps["特殊特征"]` 字符串键特征表**：`taps["X"]["红"]={...}` 语法与"模块配置"同形（RE_CFG 会被误匹配）。解析器/编译器需按值是否为特征行结构区分，否则特征库被吞进配置。
6. **GBK + `//` 注释**：`conf["jy_host"]="http://…"` 中的 `//` 在字符串内，朴素行注释剥离会截断代码；必须带字符串状态机剥离（本分析脚本踩过）。
7. **多行特征行**：特征行常超一行（p 数组、长 picName），括号平衡跨行累计时注意 `Array(` 与 `{` 混合嵌套；`UBOUND/UBound` 大小写混用（同文件两种写法并存）。
8. **死模块占比高**：4 文件未被任务链引用的模块 92/128/136/153 个（占 30%~80%）。青云决 153/192（80%）——主链 10 条任务挂起全游戏能力，其余靠任务内链与登录流程调用；但旧版确有真死代码（最强领主1/2、海神迷宫群被新版整组删除）。编译器不要按"未引用即死码"做裁剪，需区分"框架调度（登录/弹窗/线程）"与"真死码"。
9. **`任务列表` 被当模块配置污染**：`taps["任务列表"]["name"]="任务列表"` 这类配置行与特征行共存；解析时配置先行、特征按追加序，编译器应把配置键与位置特征行分开存储。
10. **表达式进入配置值**：`循环次数 = UBound(conf["礼包激活码"])+1`（青云决激活码）、`超时时间 = conf["定时任务"]["超时时间"]` —— 配置值不是字面量而是运行时表达式，编译器需保留表达式求值能力。
11. **旧版 `zxjt` 参数**：`zxjt:array("出征部队","<",5)`（龙于王者出城/地狱要塞）是按键版扩展的虚拟按键/状态判断参数，框架文档未收录；映射时按未知扩展参数透传并记录。
12. **共享目录协作风险**：本批次分析脚本曾存放于共享 `tests\_mq_analysis` 目录，被并行批次清理；分析产物最终迁移至 `tests\_mq_analysis_batchD`。多批次并行时应使用批次私有目录。

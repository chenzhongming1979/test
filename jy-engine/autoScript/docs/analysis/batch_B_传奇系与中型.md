# 批次B：传奇系与中型脚本（taps 表设计经验分析）

> 分析对象：按键精灵 .mq 脚本（JY-Frame 框架格式）批次 B 共 6 个文件。
> 语义基准：JY-Frame 框架文档（02-框架运行流程 / 16-任务模块控制命令 / 17-特征任务控制命令 / 27-防卡死机制 / 06-指令索引 / 03-变量类型定义 / 23-任务返回值）。
> 方法：Python 静态提取（GBK/UTF-8 双编码、花括号配平、`taps[...]=...` 与 `X(UBOUND(X)+1)={...}` 全量扫描），模块链按「运行后方法」边做 BFS。
> 任务参数 9 槽语义来源：`jy-frame.lua` 源码注释——`任务参数 = (启动方法,执行方法,执行模式,执行间隔时间,进入任务超时时间,是否有对应设置,执行次数,UIID,任务执行前操作)`。

**容器机制**（本批次独有的三层任务列表）：

#### 2.1.4 重点任务模块链

- **历练（41 模块 / 深度 6）**：历练 → 历练模式检查/自动历练/通用任务退出(D1) → 历练任务/练设置/自动历练地图检测/自动历练检测(D2) → 历练队伍/历练答题/进入历练(D3) → 历练花费/距离检测(D4) → 快速购买(D5)。长链采用「检查→执行→恢复」三层：`自动历练` 配置 `强制休息 + ForCheck:false`，`历练任务` 的退出方法指回 `BOOS任务`/`面板任务` 容器。
- **打修罗（31 / 6）**：打修罗 → 距离检测2/魔修罗检测/通用任务退出(D1) → 选择修罗/进入修罗(D2) → 修罗序号(D3，`任务界面` 门禁) → 当前修罗检查(Function)。检测类模块（距离检测×3 个变体）`强制休息:1000`。
- **挂机检查（28 / 7）**：挂机检查 → 前往挂机/前往荒原/当前地图/神龙大陆(D1) → 普通刷怪/神龙地图选择/进入荒原(D2) → 快速刷图/挂机/神龙boos选择(D3) → 选择boos/无怪检查(D4) → 进入地图(D5)。`挂机`/`打修罗` 等长时模块均 `ForCheck:false`。
- **新手任务（16 / 3）**：`超时时间 + 强制休息` 配置，11 特征做界面识别，运行后方法分叉到 攻击力识别/背包/英雄/转生 四条支线。
- **恢复三角**（反卡死核心资产）：

```vb
taps["通用任务退出"][1] = {"背包已满", 5, "ff":"ps", "运行后方法":"回收", ...}
taps["通用任务退出"][3] = {"立即使用", 5, "ff":"ps","isClick":false,"wait":0,"变量赋值":array(3,"立即使用","","ms"),"zxtj":array(3,"立即使用","",">",60*1000*30,"ms"),"运行后方法":"立即使用", ...}
taps["通用任务退出"][5] = {"前往活动", 5, "ff":"ps","tape":array(136,556),"aterTape":array(240,907), "out":true,"运行后方法":"前往活动", ...}
```

`通用任务退出` 在此不是框架默认的"单特征主界面检测"，而是 **12 特征的恢复大模块**（背包满→回收、红包→立即使用、活动→前往活动、治疗→前往治疗…最后 `out:true` 回主界面）。`zxtj` 值 `array(3,"立即使用","",">",60*1000*30,"ms")` 表示按 config(3) 里的时间戳字段做 30 分钟节流。

### 3.1 命名规律

### 3.2 拆分粒度

- 模块数与条目数比 ≈ 4~9 : 1（龙迹之城 240/31、JY_LM 132/26、兵人 128/22）。**模块是比任务小一级的单元**：一个任务平均由 3~8 个模块协作完成。
- 每模块特征数：中位数 2~4，上限观测 32（章节任务弹窗）/50（任务识别，分发器角色）；普通执行模块 >10 特征即开始按子步骤再拆（如 造兵通用 13 特征按兵种拆）。
- 链深分布：1 跳（占多数）→ 2~3 跳（常态）→ 4~7 跳（复杂玩法）；**7 跳是观测上限**，龙迹之城历练链 41 模块/7 层已配合大量检测哨兵与 ForCheck:false。
- 三种链形态：① 线性链（进入界面A→点B→确认C→out）；② 扇形分发（识别模块 1 → N 个并列子面板，如 军衔→兽神/军装/战灵）；③ 环形参数化（方向滑动族互相接力）。

### 3.3 复用模式（跨文件一致）

| 模式 | 定义形态 | 复用方式 | 入度观测 |
|------|----------|----------|----------|

## 4 可复用规则清单（面向编译器映射）

- **R-B01 任务列表=容器+追加**：任务列表不是字面量数组，而是 `taps["任务列表"]=Array()` 后逐条 `别名(UBOUND(别名)+1)={…}` 追加（别名经 `Dim X = taps["任务列表"]` 绑定）。编译器应把「任务列表」建模为可追加容器，支持任意 `X(UBOUND(X)+1)={…}` 追加语句归并到别名目标。
- **R-B02 条目形状**：`{任务名(与模块同名), pri=5, "ff":…, "任务参数":9槽, isClick, wait, p/ps, degree, waitOut, 执行条件, ty_n, 变量赋值}`；`ff:"nil"` 表示纯调度无入口特征。
- **R-B03 9 槽映射**：`(启动方法,执行方法,执行模式,执行间隔时间,进入任务超时时间,是否有对应设置,执行次数,UIID,任务执行前操作)`。批次B实测：槽1 恒 0；槽2 罕用（模块名"进入禁地"）；槽3 ∈{0,1}；槽4 秒表达式（60*60*2 等，含哨兵 "M"）；槽5 毫秒（20*1000）且罕用；槽6 false=无 UI 设置项；槽7/8 全空；槽9=执行前跳转的模块名或 Function 名。编译器按此语义建 AST，单位在槽级归一化。
- **R-B04 同名任务双锚点**：同一任务名出现多条（分解×2、修仙×2），参数相同仅 `p` 不同 → 映射为「单任务 + 多入口特征」，不得生成两个独立任务。
- **R-B05 注释=任务开关**：停用任务整行 `//` 保留在列表中（龙族霸业 9 条）→ 编译器需保留 enabled=false 语义，不能因忽略注释而激活任务。
- **R-B06 模块定义四件套**：`taps["M"]=Array()`（初始化）→ `taps["M"]["配置键"]=值`（0~N 条模块级配置）→ `taps["M"][i]={特征}` 或 `M(UBOUND(M)+1)={特征}`（特征行）→ 可选 `taps["M"]["name"]="M"`（自描述）。同一模块可跨行距多次拼装（获得奖励 L267/L1117）。
- **R-B07 特征行位置参数**：第 1 位=特征名（语义化元素名），第 2 位=优先级（几乎恒 5，可忽略但必须占位），其后全为 `"键":值`。
- **R-B08 跳转目标二相性**：`运行后方法` 的值若与 taps 模块同名 → 模块链；否则为自定义 Function（如 Battlefield/Hero/talk/getResType/zShopping）。编译器需建符号表区分，函数引用不得生成模块调用。
- **R-B09 退出三件套**：`out:true`（找到即退当前模块）、`notOut:true`（找不到即退）、`notFun:"恢复模块"`（找不到时先执行恢复）。三者在「识别+恢复」模块中常组合出现。
- **R-B10 outTask 拼写二相性**：真实脚本用 `outTast`/`outTastSure`（JY_LM 6+7 次、兵人 3 次），文档亦混写 outTask/outTast → 编译器两种拼写都接受并归一。
- **R-B11 空任务界面声明**：`任务界面=Array()` 大量出现但全为空 → 编译器可省略该键；真正门禁用 `ty_n` 或首特征 `notOut`。
- **R-B12 配置值变量引用**：`超时时间/强制休息/循环次数` 的值可为 `array(作用域,"表","键")`（甚至动态简写 `array("农场加速",0)`）→ 配置节点需支持「字面量 | 变量引用 | 表达式」三态。
- **R-B13 执行条件三形态**：① 数组形 `array(array(1,"任务变量",键,运算符,值),…)`；② 命名条件字符串（指向 Function，如 `"talk"`、`"Battlefield"`）；③ 自定义扩展 `zxtj`（`array(7,UI键,子键,op,值)` 读 UI 设置；扩展形 `[条件组, 未满足方法]`；`array(3,键,"",">",时间戳,"ms")` 时间节流）。映射时①→标准条件，②→谓词调用，③→UI 门禁+兜底动作。
- **R-B14 连击退出**：`outCount=N`（模块级）+ 特征 `mathchCheck:true` + 可选 `退出方法:"收尾模块"` → 映射为「连续命中 N 次退出并执行收尾」。
- **R-B15 长时模块豁免**：`ForCheck:false`（含小写 `forCheck`）→ 关闭超时/循环检查，映射为 unlimited 标志；仍建议保留兜底超时时间。
- **R-B16 方向模块折叠**：同构方向模块族（差异仅坐标/次数，且次数来自变量）→ 可折叠为「带参数模块模板 + N 个实例」，实例参数表 `(xy1,xy2,moveCount)`。
- **R-B17 分发器建模**：`循环次数=1 + 截图至内存=true + ≥10 识别特征（多为 isClick:false/ty_n）` 的模块是路由器，映射为 switch/match 节点而非顺序流。
- **R-B18 恢复三角必备**：脚本必须提供 ①`通用任务退出`（主界面回归，out:true）②`通用弹窗`（循环次数=1、截图至内存=true 的弹窗清理）③`弹窗检测`+`检测线程`（线程级哨兵）。退出方法默认指向 ①。
- **R-B19 确认弹窗一等化**：把「立即使用/获得奖励/恭喜获得」类确认处理提为公共模块（强制休息=10 或 循环次数=1），由各任务尾特征 `运行后方法` 汇入——编译器可识别「确认类 UI 事件」自动建议该复用。
- **R-B20 链深预算**：模块链建议 ≤7 跳、单任务 ≤16 模块（观测 41 为极限特例）；超过时应拆容器或引入分发器。
- **R-B21 槽9 前置钩子**：`任务执行前操作` 填模块名（出城回城/定位右下/boos界面/立即使用）或函数名（getResType）→ 编译器映射为任务 pre-hook 节点。
- **R-B22 ff 指令覆盖面**：本批次出现 `ps/ps_w/ps_s/ps_b、ft/ft_w/ft_a/ft_c/ft_res、fc_s/fc_c、pic_w/pic_c、move/moves、ocr、ty、p、nil、lz、ft-dc-ocr`。编译器首期须覆盖 `ps*、ft*、pic_w、move(s)、ocr、ty、nil、p`，它们覆盖 >95% 特征行。
- **R-B23 wait 与 waitOut 分工**：`wait`=动作后等待(ms)；`waitOut`=等待特征出现超时(ms，3000~60000)，且模块级 waitOut 观测到秒（60*5）——单位按消费方（ps_w/ft_w/pic_w 系列）处理。
- **R-B24 结果落库键**：`变量赋值`（含函数调用形 `变量赋值(true,array(...))` 与简写 `array("农场加速",0)`）、`ocrWrite/writePoint/writeConf/writeNum` 把识别结果写入变量 → 映射为特征后置写操作。

## 5 坑与反例

1. **任务指向未定义模块**：神途唯一任务「打野」无同名 taps 模块；龙迹之城「天空禁地2」同样缺失（列表里只有 天空之城2/天空禁地）。调度到时必然失败——编译器应做任务名↔模块名的静态一致性检查。
2. **键名笔误（静默失效）**：`推出方法`（应为 退出方法，JY_LM「科技研究」、兵人各 1 处）；`aterTape`（应为 afterTape，龙迹之城「通用任务退出」[5]）；`wai`（应为 wait，兵人）；`强制修仙`（应为 强制休息，龙迹之城「选择人物」）。框架不报错、配置直接被忽略——编译器要做键名模糊校验白名单。
3. **拼写二相性陷阱**：`outTast/outTask`、`ForCheck/forCheck`、`True/true`、`Array/array` 混用且框架两端都接受；映射器必须大小写/拼写归一，否则规则漏配。
4. **槽位单位不统一**：槽4 秒（60*60*2）vs 槽5 毫秒（20*1000）；waitOut 特征级毫秒 vs 模块级出现秒（60*5）；「打野」用 60*1000*1000 当"永不执行"的魔法数。语义层需要显式单位与饱和值。
5. **哨兵值 "M"**：槽4 出现 `"M"`（龙迹之城 BOOS/面板 4 条），文档未定义，疑为"手动/由脚本控制"标记——映射前需与框架实现核对，不能想当然当数字解析。
6. **空声明噪音**：`任务界面=Array()` ×100+ 全部为空、`name` 键只有部分模块写——按存在性判断会误判，需按值有效性判断。
7. **巨型分发器**：JY_LM「任务识别」50 特征、兵人「章节任务弹窗」32 特征——虽能工作，但任何一条特征色值变化都影响整模块，拆分经验是「识别特征 ≤10/模块 + 子面板独立成模块」。
8. **模块跨行距拼装**：JY_LM「获得奖励」在 L267 与 L1117 两处各写 1 个特征，中间隔 850 行——静态分析必须全文扫描合并，否则漏特征。
9. **注释依赖**：龙族霸业用 `//` 控制任务启停；若编译管线把注释当纯垃圾丢弃，会多执行 9 个任务并改变节奏。
10. **自定义扩展键外溢**：`zxtj`（UI 条件门禁，含 fallback 方法变体）、`滑动后方法`、`运行前方法`、`每次点击后方法`、`success`、`longWait`、`count+` 等大量脚本族私有键未见于框架文档——编译器需要「未知键透传」策略而非严格拒绝，同时建立扩展键登记表。
11. **通用弹窗静态入度为 0**：它由框架 notFun/notOut 兜底机制调用，静态图分析会误判为死代码——链分析必须把 `notFun` 视为隐式调用边。

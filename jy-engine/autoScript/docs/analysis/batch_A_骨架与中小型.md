## 2 框架骨架经验（来自模板 + 框架测试）

### 2.1 标准文件段落顺序（所有框架脚本一致）

```
1. Import 库        → runFun.mql（必）、HJG.lua（必）、change.lua(e)、ShanHai.lua、lzdm.lua、JYSFun.mql（按需）
2. Dim 四大容器     → Dim vars() / taps() / conf() / UIConf()   // 注释：每轮更新/特征集合/重启更新/UI设置
3. UIConf 配置      → 配置路径、配置文件名(UIS1-4.txt)、配置列表、脚本名称、高度、UIJson
4. conf 平台段      → jyGameAccount / jyGamePwd / scriptNo / scriptId / scriptAppid / jy_host
5. conf 框架段      → 开发比例、全局精确度、ms、timeout、comWait、循环次数、无特征次数、outTime、任务循环延迟…
6. conf 进阶段      → 卡屏检测系列、启动线程、线程间隔、打码(联众/验证码类型/软件ID)、改机、IP代理、定时任务
7. Function init()  → vars["任务变量"]=Array() / vars["状态变量"]=Array() / vars["内存变量"]=Array() → HJG.HJGInit(conf)
8. taps 模块区      → 按业务分组逐模块定义（通用→登录链→业务任务→退出三件套→任务列表→测试）
9. freemInit        → taps = change.freemInit(Array(开发比例), Array(GetScreenX(),GetScreenY()), Null, taps)
10. 入口调用        → runFun.scriptRun(conf["otherSet"],taps) ｜ runFun.taskTest "任务名" ｜ runFun.pageTest "模块名"
```

代码证据（模板 L8-11、L236、L249）：
```vb
Dim vars()       // 每轮更新变量
Dim taps()       // 特征集合
Dim conf()       // 重启脚本更新变量
...
taps = change.freemInit({ 720,1280 }, { GetScreenX(), GetScreenY() }, Null, taps )
...
runFun.pageTest "测试"
```

要点：
- **freemInit 是坐标适配层**：把 720×1280（或 1280×720）开发比例坐标换算到真机分辨率，必须在所有 taps 定义完成之后、init() 之前调用一次。
- **三个入口函数分工**：`scriptRun` 正式跑（读 UI 任务配置）；`taskTest "X"` 从任务列表跑单个任务（含通用任务退出收尾）；`pageTest "X"` 直接跑一个模块（调试模块用，模板/瑞亚/喊话/简游银河尾部都留有一个未注释的 pageTest）。
- **conf["游戏模式"]**：1 练号加挂机 2 挂机 3 练号 4 建号 5 单号 7 多角色（框架测试 L36 注释）。模板/瑞亚/喊话/简游后台在尾部调试区覆写为 5（单号），正式包里由 UI 决定。

### 2.2 任务列表的三种等价写法（编译器需全部支持）

```vb
' 写法A（简游银河/黎明堡垒/框架测试）：先绑定局部别名再追加
taps["任务列表"] = Array()
dim lb = taps["任务列表"]
lb(UBOUND(lb)+1) = {"城堡等级",5,"ff":"nil","任务参数":任务参数设置(0,null,0,null,null,false,null,null,null)}

' 写法B（模板）：等价，别名任意（rw）
Dim rw = taps["任务列表"]
rw(UBOUND(rw)+1) = {"打野",5,"ff":"nil","任务参数":{ 0,null,0,20,null,null,null,null,null}}

' 写法C（简游银河早期段落/瑞亚部分）：直接下标，允许跳号
taps["任务列表"][1] = {"奖励",5,"ff":"ps",...}
taps["任务列表"][3] = {"探险",5,"ff":"ps",...}   // [2] 被注释掉，索引不连续
```

要点：
- 局部别名绑定（`Dim lb = taps["任务列表"]`）后，`lb(UBOUND(lb)+1)` 与 `taps["任务列表"][N]` 语义相同；UBOUND 追加式是主流（框架测试 50 条全用它）。
- 直接下标式允许跳号（被注释的条目留下空洞），编译器不能假设索引连续。
- 模板 L226 留有 9 槽位官方注释，是任务参数语义的权威证据：
```vb
//任务参数设置(启动方法,执行方法,执行模式,执行间隔时间,进入任务超时时间,是否有对应设置,执行次数,UIID,任务执行前操作)
```

### 2.3 任务参数 9 槽位的实际用法（按批次 A 全部 77 条归纳）

| 槽位 | 官方语义 | 实际取值样本 |
|------|----------|--------------|
| 1 启动方法 | 任务开始前运行的模块/方法 | `null`（绝大多数）、`"造兵通用"`、`"升级建筑"`（框架测试条目，跳转到指定前置模块）、`1`（王城"训练士兵"等，数字型开关） |
| 2 执行方法 | 任务主模块覆盖 | `null`（任务名即模块名）、`"造兵通用"`、`"造兵通用界面"`、`"升级建筑"`（多个任务名共享同一执行模块） |
| 3 执行模式 | 0/1/3 | `0`（默认）、`3`（黎明堡垒"采集"条目）、王城 slot1=1 |
| 4 执行间隔时间 | 冷却秒数 | `null`、`20`（模板打野）、`60*60*4`（框架测试造兵类）、`60*60*2`（瑞亚领取奖励）、`60*60*5/6`（铁匠铺/商城/福利） |
| 5 进入任务超时时间 | 界面等待上限 | `null`（几乎全为 null） |
| 6 是否有对应设置 | UI 开关位 | `null`、`false`（框架测试约 12 条 false，其余脚本偶见） |
| 7 执行次数 | 每轮执行上限 | `null` 为主 |
| 8 UIID | UI 关联 | `null` |
| 9 任务执行前操作 | 前置动作模块 | `null`、`"治疗士兵滑动"`（框架测试 L2440：先跑滑动模块再进主任务） |

### 2.4 条目上的通用界面判定 ty_n

任务列表条目大量携带 `"ty_n":"主界面"`（瑞亚/喊话/黎明堡垒），含义与防卡死文档 2.7 一致：执行前用"通用特征库中名为主界面的特征"确认在主界面才点击。配合各脚本自建的 `taps["任务界面"]`/`taps["通用"]` 字典模块。

### 2.5 模块定义的两种形态

```vb
' 形态1：顺序特征数组（99% 的模块）
taps["进入游戏"] = Array()
taps["进入游戏"]["超时时间"] = 60*3        // 模块级配置（["键"]=值）
taps["进入游戏"][1] = {"主界面",5,"ff":"ps",...}   // 特征行（[N]={...}）

' 形态2：特征字典（瑞亚/喊话/黎明堡垒/框架测试 的"通用"模块）
taps["通用"] = Array()
taps["通用"]["主界面"] = {"主界面", 5, "ff":"ps_b", "ps":array(...), ...}
taps["通用"]["回城"]   = {"回城", 5, "ff":"ps", "p":"...", "degree":0.9}
```
`通用` 模块是**命名特征库**：`ty_n:"主界面"` 等引用按名字到这里取特征，模块本身不参与任务调度。编译器映射时应把 `taps["通用"]["X"]` 识别为"特征常量定义"而非"任务步骤"。

## 3 逐任务分析

### 3.1 模板(efcab5d8) —— 1 个任务：打野

**任务列表条目**（L229）：
```vb
rw(UBOUND(rw)+1) = {"打野",5,"ff":"nil","任务参数":{ 0,null,0,20,null,null,null,null,null}}
```
- 任务名=打野 | 优先级(超时)=5 | ff=nil（无画面操作，纯调度标记） | 9槽位=[0,null,0,20,…]（每 20 秒可重复） | 无 p/isClick/wait。

**模块链**：`打野` 模块（循环次数=1）→ 特征 `{"打野",5,"ff":"nil","success":true}` → ff=nil 默认成功 + success 记录 → 正常退出 → 框架自动走 `通用任务退出`。
- 这是"最小任务"的样板：任务列表条目 + 同名模块 + nil 特征，用于占位/测试调度链路。

**辅助链（登录，非任务列表直连）**：
`登录游戏`(超时方法=loginBack, 截图至内存) → 指挥[执行条件 appidNum==0, out→新快登陆] / 新快注册[out→新快登陆] → `新快登陆`(超时60s, loginBack) → 指挥2[out→新快登陆2] → 输入账号/输入密码（ff=p + input{2,"当前账号"}+clean） → 登录特征[out→进入游戏] / 实名认证[out→进入游戏] / 登录特征[notFun=进入游戏, notOut] → `进入游戏`(超时180s, 强制休息1000) → 主界面[ff=nil, out, 变量赋值{"登录状态","1"}]。
- 亮点：**进入游戏的 out 特征用 ff=nil + p 比色串**（只检测不点击），检测到即 out 并标记登录状态——"检测型出口"惯例。
- 防卡死三件套齐全：`弹窗检测`(超时20s 主界面 notFun=通用弹窗) / `通用弹窗`(循环1+截图至内存，本体为空) / `通用任务退出`(超时20+循环1，主界面 out notFun=通用弹窗)。

代表性条目：


**滑动99**（循环次数=3）：渠道 4/5 各一组 滑动+领取 特征，末条 `{"通用任务退出",5,"ff":"nil","out":true,"执行条件":(渠道==3),"wait":10000,"运行后方法":"通用任务退出"}`——**特征名直接写目标模块名 + ff=nil + 运行后方法** 的显式跳转惯例。

### 3.3 王城备份(e5435553) —— 12 个任务

**任务列表**（L834-848，`Dim 任务列表 = taps["任务列表"]`）：主城9、vip礼包1、使用技能1(间隔4h)、新手签到4、邮件7、任务奖励7、竞技9、龙巢9、升级主城1(isClick=false)、训练士兵1(slot1=1 + runFun:"训练士兵定位")、城内建筑任务1(slot1=1,slot6=false + runFun:"出城回城")、收集资源1(slot1=1,slot6=false + runFun:"出城回城")。

独有特征：
- **条目级 `runFun` 字段**（训练士兵→训练士兵定位；城内建筑任务/收集资源→出城回城）：任务开始前强制先跑一个"定位/回城"模块。这与 slot9"任务执行前操作"语义重叠，但写在条目属性上——编译器两种都要支持。
- **`"z":Rect(x1,y1,w-x1,h-y1)` 区域写法**：`ft` 指令的查找区域用 Rect() 表达（`"z":Rect( 928,636,1007-928,704-636)`，等价 r 数组），是按键精灵本地化的坐标习惯。
- **条目/特征用 `任务参数设置(...)` 函数而非 Array()**：返回 9 元数组，写法更紧凑。
- **全部模块定义收拢在 `Function` 内**，`Dim pages= getTaps()` 取回后 `runFun.taskTest "收集资源", pages, vars, conf`——**模块定义可函数化**（便于多页面切换/上传），入口可传显式 taps。
- 模块级配置多为 `["name"]="模块名"` 自描述 + 循环次数（如 返回检测 循环3、竞技礼包 循环6、战役定位 循环10）。
- 出口链典型：`联盟` → 联盟礼物/城市管理/联盟互助（ft-s 循环点击直到消失 + 运行后方法）→ 各自 notOut/out 收尾。

## 4 模块拆分经验

### 4.1 命名规律

| 前缀/后缀 | 含义 | 实例 |
|-----------|------|------|
| `X退出` / `退出X` | 模块的出口/收尾专用模块 | 升级建筑退出、英雄操作退出、军团捐献退出、采集资源退出、返回检测退出、打野出征退出 |
| `X界面` / `界面X` | 界面级中转/识别模块 | 矿场界面、加速界面、情报界面、造兵通用界面、章节任务界面 |
| `X判断` / `检查` / `检测` | 条件分支模块 | 矿井滑动判断、升级建筑前往判断、出征检查、返回检测、上阵检测 |
| `X通用` / `通用X` | 多任务共享的流程模块 | 造兵通用、升级建筑（被升级主城/联盟大厅复用）、通用弹窗、通用任务退出 |
| `X定位` | 进入前的位置校正 | 训练士兵定位、训练士兵定位退出、战役定位 |
| 数字/单字特征名 | 快速步骤（1、2、3、加、白、绿…） | 瑞亚斥候管理 {"1","2","3"}、黎明堡垒情报五色 |
| `主界面`/`城内`/`回城` | 惯用的界面锚特征名 | 几乎每个脚本都有 |

### 4.2 拆分粒度

- **一个 UI 任务 = 一条任务列表条目 + 1~N 个模块**：简单任务单模块（喊话）；复杂任务拆"入口模块 + 执行模块 + 出口模块"（王城：升级主城→升级建筑→升级建筑退出）。
- **入口/执行/出口三分**：入口模块负责"到达目标界面"（前进方向），执行模块负责"在界面上循环操作"（可配循环次数/无特征次数），出口模块负责"清理回主界面"（多带 退出方法 或 out）。
- **共享流程上提**：多条任务链共用的步骤提为 `X通用`（框架测试造兵 4 任务共用"造兵通用"；简游银河两条链共用"出征退出"）。
- **识别特征入库**：跨模块复用的比色特征放 `taps["通用"]` 字典（瑞亚/喊话/黎明堡垒），条目用 `ty_n` 引用。
- **出口统一收口**：任何模块退出后框架调 `通用任务退出`；任务链内部先走专用 `X退出`（弹窗清理/回城），再落回主界面。防卡死三件套（弹窗检测/通用弹窗/通用任务退出）在 9 个脚本中有 8 个完整出现，定义高度一致（循环次数=1 + 截图至内存 + notFun=通用弹窗 + out=true）。

### 4.3 复用模式清单

1. **执行方法复用**（slot2）：多任务名 → 同一执行模块（框架测试造兵系）。
2. **出口分流**：单出口模块按 conf["当前任务"] 分发（简游银河 出征退出）。
3. **前置定位**：条目级 `runFun` 或 slot9 指定进入前先跑定位模块（王城 出城回城/训练士兵定位；框架测试 治疗士兵滑动）。
4. **渠道分支**：同一模块内按 `任务变量.appidNum`（渠道号）+ 执行条件多路分支（框架测试通用弹窗、黎明堡垒登录）。
5. **幂等标志**：执行条件 `X~="1"` + 变量赋值 `X="1"` 成对（简游银河 前往1~4），跨循环防重复。
6. **冷却时间戳**：执行条件内嵌 `HJG.getTime()-HJG.fileGetUser(...) > N` + writeConf 持久化（王城 龙巢 7 天冷却）。
7. **等待模块**：`强制休息` + 单特征 out（瑞亚 等待返回）；或 `ForCheck=false` 长驻（瑞亚 刷探索）。

## 5 可复用规则清单（面向编译器映射）

- **R-A01 文件骨架固定序**：Import→Dim 四容器→UIConf→conf(平台→框架→进阶)→init()→taps 区→freemInit→入口。编译器按此序解析段落；`change.freemInit(开发比例, 真机比例, Null, taps)` 触发坐标换算，之后不得再定义模块。
- **R-A02 任务列表条目结构**：`{任务名, 超时/优先级, "ff":指令, "任务参数":9槽位, "isClick", "wait", "ty_n", "执行条件", "clickRange", "runFun", "变量赋值", p/ps/r…}`。任务名先解析为同名模块；slot2 执行方法非 null 时改用该方法名作为执行模块。
- **R-A03 任务参数 9 槽位**：按模板 L226 官方注释映射 [启动方法,执行方法,执行模式,执行间隔时间,进入任务超时时间,是否有对应设置,执行次数,UIID,任务执行前操作]；1/2/9 为模块名引用，4 为秒冷却（支持 60*60*N 表达式），其余多为 null/false 占位。
- **R-A04 条目追加语法归一化**：`X(UBOUND(X)+1)=`、`taps["X"][N]=`、局部 `Dim a = taps["X"]` 绑定、`任务参数设置(...)` 函数式参数、`Rect()` 区域 —— 五种写法语义等价，索引可跳号，注释行条目应剔除但保留行号。
- **R-A05 模块定义三段式**：`taps["名"]=Array()` 定义 → 若干 `taps["名"]["配置键"]=值` 模块级配置 → 若干 `[N]={特征}`。配置键白名单：超时时间/超时方法/无特征次数/循环次数/无特征运行/退出方法/任务界面/waitOut/执行条件/强制休息/截图至内存/卡屏不退/顺序执行/outCount/name/任务列表。
- **R-A06 特征行结构**：`{名称, 优先级, "ff":指令, 控制字段…}`；控制字段全集见频次表（运行后方法/out/notOut/outTast/notFun/waitOut/wait/isClick/input/tape/afterTape/notTape/clickRange/执行条件/变量赋值/执行一次/执行次数/timeLag/success/mathchCheck/ty_n/z/writePoint/ocrWrite…）。优先级数字越小越优先（王城 1=最高先试，9=兜底），同时是 ps_w 类的等待秒参数。
- **R-A07 跳转语义**：`运行后方法`=找到后跳模块；`out`=找到即退出本模块；`notOut`=没找到退出；`notFun`=没找到运行备胎模块/方法；`outTast`=退出整个任务链回任务列表；三者组合 = "成功链/失败链/终止链"三路控制。映射时编译器应生成等价的链式跳转图。
- **R-A08 防卡死三件套内置化**：编译器为每个脚本自动注入 `弹窗检测`/`通用弹窗`(循环1+截图至内存)/`通用任务退出`(主界面 out + notFun=通用弹窗) 模板，允许脚本侧覆盖（各脚本仅 p 串不同）。`检测线程` 对应 conf 卡屏检测开关。
- **R-A09 通用特征库**：`taps["通用"]["名"]={特征}` + `ty_n:"名"` 引用 → 编译器映射为命名特征常量；条目/特征带 `ty_n` 时先做界面锚定再执行动作。
- **R-A10 执行条件系统**：`[作用域,"表","键",op,值]` 作用域 1=vars 任务变量/状态变量/内存变量、2=conf、3=config、4=Thread、7=readUI；支持数组包数组（AND）、`array("or",…)`（OR）、裸字符串（truthy）、任意表达式。模块级（整个模块门控）与特征级（单特征门控）同构。
- **R-A11 变量赋值系统**：`[作用域,"组","键",值,"类型",flag]`；值可为嵌套读取 `[作用域,…]`、特殊值 day/time/ms、简写 `{"键","值"}`；`变量赋值(true, Array([...]))` 批量形态；ocrWrite/ocrWrite 类字段直接写 vars。
- **R-A12 幂等/冷却惯用法**：编译器遇到"条件 X~=1 + 赋值 X=1"对时，可优化为一等公民"仅一次"节点；遇到 getTime-fileGetUser 冷却表达式时映射为持久化冷却节点。
- **R-A13 入口三函数**：scriptRun(正式)/taskTest(单任务)/pageTest(单模块调试)。编译器应保留调试入口生成开关；`conf["当前任务"]`/`conf["游戏模式"]` 是调度器状态位。
- **R-A14 ff 指令覆盖面**：批次 A 实际用到 ps,ps_w,ps_s,ps_b,ps_bw, ft,ft_w,ft_a,ft_s,ft_res, ft-dc-ocr, pic_c,pic_w,pic_a, fc_c,fc_s, p,2p,pi类, move,moves, rand,ocr,gcn,rApp,ty,nil。ps 系占 72%，编译器优先保证 ps/ft/pic/nil 四族的映射完备性。
- **R-A15 多值参数**：picName 支持 `a.png|b.png` 管道多图；ps 数组支持多色点 OR（ps_b）；`p` 串逗号分隔多点比色 `x|y|color-delta`；`notTape` 排除点；`clickRange` 收缩命中点击范围。

## 6 坑与反例

1. **编码陷阱**：全部 9 个文件实际为 GBK（utf-8 解码失败后 fallback），且按键 GBK 文本中大量中文键名（运行后方法/任务参数/无特征次数）。任何解析器必须先 utf-8-sig→utf-8→gbk 三段探测，否则字段名全损。
2. **注释即功能开关**：任务列表条目、特征行、入口调用被 `//` 注释是常态（简游银河 [2][5]、框架测试 [举报脚本]、简游后台全部入口）。"看起来定义了"不等于"参与调度"，解析必须剔除注释行；同时注释掉的入口是理解作者调试意图的线索。
3. **索引空洞**：`taps["任务列表"][1]/[3]/[6]` 跳号（简游银河），UBOUND 追加与下标直写混用——不能用"数组长度=条目数"做任何假设。
4. **同名异义**：`任务列表` 既是数组模块名又是模块级配置键（`taps["BOOS任务"]["任务列表"]=true`，瑞亚）；`超时时间` 在条目第 2 位是"优先级/等待秒"，在模块配置里是"模块秒级超时"，在特征 `waitOut` 里又是毫秒——单位与层级双重歧义，需按上下文区分。
5. **空占位配置**：框架测试 41 处 `["任务界面"]=Array()` 空数组、多个空模块（瑞亚 选区、喊话 任务界面）——字段存在但无值是"声明未启用"，不是数据缺失。
6. **调用不存在模块**：模板 `新快登陆.指挥2 → 运行后方法:"新快登陆2"`，但模板未定义 `新快登陆2`（依赖框架或残缺）。编译器校验"跳转目标必须存在"时应告警而非报错终止。
7. **GBK 乱码残留**：黎明堡垒等文件在 UTF-8 工具里直接读会花屏；王城备份注释掉的区域（Rect 负坐标写法 `704-636`）是表达式而非字面值，直接按数字解析会错。
8. **配置键拼写漂移**：`超时退出=30*1`（框架测试 远征退出）vs 标准名 `超时时间`；`outTask` vs `outTast`（文档 17 章两种拼写并存）——映射表必须收录别名。
9. **执行条件内嵌表达式**：王城 `执行条件:(HJG.getTime()-HJG.fileGetUser(...) > 60*60*24*7)`、简游银河 `ReadUIConfig("矽导") = true`——条件值可能是任意脚本表达式而非五元组，解析器要能识别"非数组即表达式"。
10. **过程式混入**：新建脚本完全没有 taps（纯 Function+startX）；脚本内还有 `While true KillApp(...)`（框架测试尾部）这类调试残留——编译器输入需容忍"框架区+自由代码区"共存，自由区原样保留。
11. **入口函数改名**：王城把模块区包进 `getTaps()` Function 并 `Dim pages= getTaps()` 再 `taskTest "收集资源", pages, vars, conf`（多传一个 vars/conf）——入口签名不唯一。
12. **模块级 `wait` 配置**：简游银河 通用任务退出 `["wait"]=500`（配置键 wait 不在文档 5.1 模块属性表内）——真实脚本会发明文档之外的模块级键，编译器需白名单+透传策略。

## 1. 总体说明

AutoScript 由 6 个 Python 脚本文件组成，每个文件自包含（核心函数 + CLI 入口）。Trae AI 按 `trae/rules.md` 调度这些脚本完成全流程。

每个文件的结构规范：

```python
# scripts/xxx.py
"""模块说明"""
import ...

# === 配置 ===
DEFAULT_CONFIG = {...}

# === 核心函数（迁移时直接 import，零改动）===
def func1(...): ...
def func2(...): ...

# === 内部工具 ===
def _helper(...): ...

# === CLI 入口 ===
def main():
    parser = argparse.ArgumentParser()
    sub = parser.add_subparsers(dest="cmd")
    ...
    args = parser.parse_args()
    result = dispatch(args)
    print(json.dumps(result, ensure_ascii=False))

if __name__ == "__main__":
    main()
```

## 2. adb.py — 设备连接与操作

### 2.1 职责

封装 ADB 命令，提供设备连接、截图、点击、滑动、输入、按键等操作，以及环境检查（doctor）。

### 2.2 核心函数

| 函数 | 参数 | 返回 | 说明 |
|------|------|------|------|
| `get_devices()` | - | `list[dict]` | 列出已连接设备 |
| `get_resolution(device_id)` | device_id | `(w, h)` | 获取设备分辨率 |
| `screenshot(device_id, save_path)` | device_id, save_path | `str`（路径） | 截图并保存 |
| `click(device_id, x, y)` | device_id, x, y | `bool` | 点击 |
| `swipe(device_id, x1, y1, x2, y2, duration)` | device_id, 坐标, 时长 | `bool` | 滑动 |
| `long_press(device_id, x, y, duration)` | device_id, 坐标, 时长 | `bool` | 长按 |
| `input_text(device_id, text)` | device_id, text | `bool` | 输入文字 |
| `keyevent(device_id, key)` | device_id, key(back/home) | `bool` | 按键 |
| `wait_stable(device_id, timeout_ms)` | device_id, 超时 | `bool` | 等待画面稳定 |
| `doctor()` | - | `dict` | 环境检查 |

### 2.3 CLI 命令

```bash
python scripts/adb.py doctor
python scripts/adb.py devices
python scripts/adb.py screenshot --device <id> --output <path>
python scripts/adb.py click --device <id> --x <x> --y <y>
python scripts/adb.py swipe --device <id> --x1 <x1> --y1 <y1> --x2 <x2> --y2 <y2> --duration <ms>
python scripts/adb.py input --device <id> --text "<text>"
python scripts/adb.py keyevent --device <id> --key <back|home>
python scripts/adb.py resolution --device <id>
```

### 2.4 实现要点

- 用 `subprocess.run` 调用 adb，设置 `timeout=10`
- 截图用 `adb exec-out screencap -p > <path>`（比 `adb shell screencap` 快，避免 base64）
- `wait_stable`：连续截图比较 phash，差异 < 阈值则稳定
- `doctor`：逐项检查，汇总通过/失败/警告

### 2.5 错误码

| 错误码 | 说明 |
|--------|------|
| `ADB_NOT_FOUND` | adb 命令不可用 |
| `DEVICE_NOT_FOUND` | 设备未连接 |
| `SCREENSHOT_FAILED` | 截图失败 |
| `INPUT_TIMEOUT` | 操作超时 |

## 3. analyze.py — 界面分析

### 3.1 职责

对截图进行多模态分析，输出结构化界面描述（可点击元素、文字、界面标签）。采用视觉 LLM + OCR 双重融合。

### 3.2 核心函数

| 函数 | 参数 | 返回 | 说明 |
|------|------|------|------|
| `analyze_screen(image_path, model_config)` | 图片路径, 模型配置 | `ScreenState` | 主分析入口 |
| `vision_analyze(image_path, prompt, model_config)` | 图片, prompt, 配置 | `dict` | 调用视觉 LLM |
| `ocr_recognize(image_path, region=None)` | 图片, 可选区域 | `list[dict]` | RapidOCR 识别 |
| `fuse_elements(vision_elements, ocr_elements)` | 两路元素 | `list[UIElement]` | 按 bbox 重叠度合并 |
| `is_native_layout(image_path)` | 图片 | `bool` | 判断是否原生控件界面（启发式） |

### 3.3 视觉 LLM Prompt

```
你是安卓界面分析专家。分析这张截图，返回严格 JSON。

要求：
1. 识别所有可交互元素（按钮/图标/列表项/输入框/标签页）
2. 每个元素：type, text, bbox[x1,y1,x2,y2], confidence, is_primary
3. 判断当前界面语义标签（主界面/副本选择/战斗中/背包/设置/弹窗/加载中...）
4. 简要描述界面

返回：
{"scene_label": "...", "elements": [...], "description": "..."}
只返回 JSON。
```

### 3.4 CLI 命令

```bash
python scripts/analyze.py --image <path> [--ocr-only] [--vision-model <model>] [--output <json_path>]
```

### 3.5 输出格式

```json
{
  "status": "ok",
  "data": {
    "scene_label": "主界面",
    "description": "游戏主界面，底部有功能按钮",
    "elements": [
      {
        "id": "elem_001",
        "type": "button",
        "text": "副本",
        "bbox": [300, 1100, 420, 1200],
        "center": [360, 1150],
        "confidence": 0.95,
        "is_primary": true
      }
    ],
    "texts": [{"text": "等级 50", "bbox": [50, 30, 150, 60]}]
  }
}
```

### 3.6 实现要点

- 视觉 LLM 调用复用 Trae 配置（从 config/models.yaml 读取）
- OCR 用 RapidOCR，支持中文
- 元素融合：bbox IoU > 0.5 则合并，取并集，文字取 OCR 结果（更准）
- 低置信度元素（< 0.5）标记为 `uncertain`，AI 决策时优先选高置信度

## 4. feature.py — 特征处理

### 4.1 职责

稳定色点采样、感知哈希计算、画面变化检测。这是自动生成 ps 特征的核心。

### 4.2 核心函数

| 函数 | 参数 | 返回 | 说明 |
|------|------|------|------|
| `sample_stable_points(image_path, bbox, count=3)` | 图片, 区域, 点数 | `list[dict]` | 采样稳定色点 |
| `compute_phash(image_path)` | 图片 | `str` | 感知哈希（64位十六进制） |
| `compare_screens(before_path, after_path)` | 两张图 | `dict` | 画面变化检测 |
| `verify_points(image_path, points)` | 图片, 色点列表 | `dict` | 验证色点匹配率 |
| `generate_ps_param(points)` | 色点列表 | `str` | 生成 ps 指令的 p 参数 |

### 4.3 稳定色点采样算法

1. 裁剪 bbox 区域，向外扩 2px
2. 转灰度，计算每个像素 5×5 邻域方差
3. 筛选候选点：
   - 方差 < 50（低方差 = 颜色稳定）
   - 与背景对比度 > 30
   - 不在边缘 3px 内
4. 选 count 个点，点间距离 > 元素尺寸的 1/3
5. 色值 = 该点 RGB；偏色 = max(邻域方差 × 2, 0x101010)，上限 0x303030
6. 多帧验证：在当前帧和后续 2 帧验证匹配率，< 90% 则重新采样

### 4.4 感知哈希

- 缩放至 32×32 → DCT → 取左上角 8×8 → 均值二值化 → 64 位哈希
- 汉明距离 < 5 认为是同一界面

### 4.5 画面变化检测

```json
{
  "phash_distance": 12,
  "changed": true,
  "change_regions": [[100, 200, 300, 400]],
  "similarity": 0.85
}
```

### 4.6 CLI 命令

```bash
python scripts/feature.py sample --image <path> --bbox <x1,y1,x2,y2> [--count 3]
python scripts/feature.py phash --image <path>
python scripts/feature.py compare --before <path1> --after <path2>
python scripts/feature.py verify --image <path> --points <json>
```

### 4.7 色点输出格式

```json
{
  "status": "ok",
  "data": {
    "points": [
      {"x": 324, "y": 1207, "color": "837C75", "tolerance": "101010"},
      {"x": 357, "y": 1205, "color": "F5E7CE", "tolerance": "101010"}
    ],
    "ps_param": "324|1207|837c75-101010,357|1205|f5e7ce-101010",
    "verify_hit_rate": 1.0
  }
}
```

## 5. coordinate.py — 坐标换算

### 5.1 职责

真实像素坐标与 JY-Frame 设计坐标之间的换算，采用**九宫格锚点系统**实现全分辨率适配。锚点由控件在屏幕中的位置自动判断。

### 5.2 九宫格锚点系统

屏幕分为 3×3 九宫格，控件中心落在哪个格子，锚点就是对应编号：

```
┌─────┬─────┬─────┐
│  1  │  2  │  3  │   1=左上  2=上中  3=右上
├─────┼─────┼─────┤
│  4  │  5  │  6  │   4=左中  5=中心  6=右中
├─────┼─────┼─────┤
│  7  │  8  │  9  │   7=左下  8=下中  9=右下
└─────┴─────┴─────┘
```

**设计目的**：不同分辨率下，控件相对其"靠拢方向"的位置保持不变。例如底部菜单往下靠 → 锚点 8，宽屏手机上底部菜单仍贴底，不会跑到屏幕中间。

### 5.3 核心函数

| 函数 | 参数 | 返回 | 说明 |
|------|------|------|------|
| `real_to_design(x, y, real_res, design_res, anchor)` | 真实坐标, 分辨率, 锚点(1-9) | `(x, y)` | 真实→设计 |
| `design_to_real(x, y, real_res, design_res, anchor)` | 设计坐标, 分辨率, 锚点(1-9) | `(x, y)` | 设计→真实 |
| `detect_anchor(center_x, center_y, screen_w, screen_h)` | 控件中心, 屏幕尺寸 | `int` (1-9) | 根据控件位置自动判断锚点 |
| `detect_resolution(device_id)` | device_id | `(w, h)` | 检测设备分辨率 |

### 5.4 换算公式

设设计分辨率 `(Wd, Hd)`，实际分辨率 `(Wr, Hr)`，缩放比 `sx = Wr/Wd`，`sy = Hr/Hd`。

**设计→真实（design_to_real）**：

| 锚点 | x 换算 | y 换算 |
|:----:|--------|--------|
| 1 左上 | `x * sx` | `y * sy` |
| 2 上中 | `Wr/2 + (x - Wd/2) * sx` | `y * sy` |
| 3 右上 | `Wr - (Wd - x) * sx` | `y * sy` |
| 4 左中 | `x * sx` | `Hr/2 + (y - Hd/2) * sy` |
| 5 中心 | `Wr/2 + (x - Wd/2) * sx` | `Hr/2 + (y - Hd/2) * sy` |
| 6 右中 | `Wr - (Wd - x) * sx` | `Hr/2 + (y - Hd/2) * sy` |
| 7 左下 | `x * sx` | `Hr - (Hd - y) * sy` |
| 8 下中 | `Wr/2 + (x - Wd/2) * sx` | `Hr - (Hd - y) * sy` |
| 9 右下 | `Wr - (Wd - x) * sx` | `Hr - (Hd - y) * sy` |

**真实→设计（real_to_design）**：上述公式的逆运算。

**锚点自动判断**：
```python
def detect_anchor(center_x, center_y, screen_w, screen_h):
    col = 0 if center_x < screen_w / 3 else (1 if center_x < screen_w * 2 / 3 else 2)
    row = 0 if center_y < screen_h / 3 else (1 if center_y < screen_h * 2 / 3 else 2)
    return row * 3 + col + 1  # 返回 1-9
```

### 5.5 CLI 命令

```bash
python scripts/coordinate.py convert --x <x> --y <y> --from real --to design --resolution <w,h> --anchor <1-9>
python scripts/coordinate.py detect-anchor --x <center_x> --y <center_y> --resolution <w,h>
python scripts/coordinate.py detect --device <id>
python scripts/coordinate.py verify --device <id> --test-point <x,y> --anchor <1-9>
```

### 5.6 验证方法

开发完成后必须验证：
1. 在已知分辨率设备上，取一个真实坐标和对应锚点
2. 换算为设计坐标
3. 用 JY-Frame 脚本在同设备上运行，确认点击位置一致
4. 测试 9 种锚点各至少一个用例
5. 跨分辨率验证：在 720p 和 1080p 设备上分别测试，确认锚点适配正确

## 6. compile.py — 脚本编译

### 6.1 职责

将运行时状态机（JSON）编译为 JY-Frame `taps` 表脚本，支持多平台输出。

### 6.2 核心函数

| 函数 | 参数 | 返回 | 说明 |
|------|------|------|------|
| `load_state_machine(run_id)` | run_id | `dict` | 加载状态机 JSON |
| `de_explore(state_machine)` | 状态机 | `dict` | 去探索化（过滤失败路径） |
| `build_modules(state_machine)` | 状态机 | `list[dict]` | 构建任务模块 |
| `build_task_list(modules)` | 模块列表 | `list[dict]` | 构建任务列表 |
| `render_template(modules, task_list, platform)` | 模块, 平台 | `str` | jinja2 渲染 |
| `compile(run_id, platform, output_path)` | 全参数 | `str` | 主编译入口 |

### 6.3 映射规则

| Agent 概念 | JY-Frame 概念 | 生成方式 |
|-----------|--------------|---------|
| 界面状态 | 任务模块 `taps.状态名` | scene_label + 序号 |
| 元素 + 稳定色点 | `ff="ps", p="..."` | 用 feature.py 生成的 ps_param |
| 状态转移（A→B） | `运行后方法="B"` | 取成功次数最高的转移 |
| 到达目标状态 | `out=true` | 任务终止状态 |
| 循环操作（同状态重复>3次） | `ff="ps_s", bigCount=N` | 自动检测 |
| 等待界面 | `ff="ps_w", waitOut=...` | 从验证等待时长推断 |
| 模块超时 | `超时时间 = N` | 实际耗时 × 1.5 |

### 6.4 去探索化

1. 过滤 success=false 的转移
2. 同一 from→to 的多次尝试只保留成功的
3. 异常界面有成功关闭操作的 → 生成弹窗处理模块
4. 无成功处理的 → 脚本注释标注"需人工处理"

### 6.5 CLI 命令

```bash
python scripts/compile.py --run-id <id> --platform <lua|vb|js|go> --output <path>
python scripts/compile.py list-runs
python scripts/compile.py inspect --run-id <id>  # 查看状态机摘要
```

### 6.6 输出示例（Lua）

```lua

-- 生成时间: 2026-09-11 14:30:00

    {"火副", 5, ff="ps", p="563|369|FAF7E7-101010", degree=0.9,
```

## 7. models.py — 数据结构

### 7.1 职责

定义通用数据结构（dataclass），提供 JSON 序列化/反序列化。被其他脚本 import。

### 7.2 数据结构

```python
@dataclass
class UIElement:
    id: str
    type: str           # button/icon/list_item/input/tab/text
    text: str
    bbox: tuple         # (x1,y1,x2,y2)
    center: tuple       # (x,y)
    confidence: float
    is_primary: bool = False
    stable_points: list = field(default_factory=list)

@dataclass
class ScreenState:
    state_id: Optional[int]
    scene_label: str
    description: str
    elements: list[UIElement]
    texts: list
    phash: str
    screenshot: str
    timestamp: float

@dataclass
class Action:
    type: str           # click/swipe/input/wait/back/home
    coord: Optional[tuple]
    swipe_from: Optional[tuple]
    swipe_to: Optional[tuple]
    expected_scene: str
    reason: str

@dataclass
class Feature:
    name: str
    ff: str             # ps/ps_s/ps_w/ft/...
    ps_param: str       # p 参数
    degree: float
    out: bool
    next_method: str
    anchor: int         # 九宫格锚点 1-9，编译时坐标换算用

@dataclass
class Transition:
    from_state: int
    to_state: int
    action: Action
    success: bool
    timestamp: float
```

### 7.3 序列化

每个 dataclass 提供 `to_dict()` 和 `from_dict()` 方法，用于 JSON 存取。

## 8. 模块间调用关系

```
analyze.py ──import──▶ models.py
    │
    ▼
feature.py ──import──▶ models.py
    │
    ▼
compile.py ──import──▶ models.py
    │
    ▼
coordinate.py（独立，被 compile.py 调用）

adb.py（独立，不依赖其他模块）
```

**调用原则**：
- `models.py` 是底层，被所有模块 import
- `adb.py`、`coordinate.py` 独立，不依赖其他业务模块
- `analyze.py`、`feature.py`、`compile.py` 只依赖 models.py
- 模块间不互相 import（避免循环依赖），通过 JSON 文件传递数据

# CLA 签署指引（贡献者必读）

> 本文档指导你完成 [CLA.md](CLA.md)（贡献者许可协议）的签署。**首次贡献前必须完成**；已签署者后续 PR 勾选声明即可。

## 一、为什么需要签署

JY-Engine 采用 **GNU AGPL-3.0** 主许可 + **商业授权**双许可模式（同 MySQL/Qt）：遵守 AGPL（含网络服务开源义务）免费使用；**闭源商用或不受 AGPL 约束的商业使用须向项目方购买商业授权**。签署 CLA 的目的是**一次性明确双方权利**：你保留贡献的完整版权；同时特别授权项目方对贡献的商业许可权（含闭源商业发行）——没有这一条，项目方自己也无法商业运营包含你贡献的版本。

## 二、谁需要签署

| 你的情况 | 需要做什么 |
|---|---|
| 首次贡献（未在 [CLA-SIGNED.md](CLA-SIGNED.md) 名单） | 完成下方完整签署流程 |
| 已在名单中 | 提 PR 时勾选声明即可 |
| 以企业/公司名义贡献 | 暂不支持标准流程，请先联系维护者 |

## 三、签署步骤

### 步骤 1：阅读协议

通读 [CLA.md](CLA.md) 全文（约 3 分钟），重点理解：

- **第 2 条**：你授予项目方的许可（a 项 AGPL 授权 + **b 项商业许可授权**，双许可模式的基础）
- **第 4 条**：版权归属（许可而非转让；你对自己的贡献可自行商用）
- **第 5 条**：你的原创性保证

### 步骤 2：提交签署 Issue

1. 打开仓库 Issues 页 → **新建 Issue**
2. 标题格式：`签署 CLA：@你的Gitee用户名`
3. 正文复制以下模板并如实填写：

```markdown
我已阅读并完全同意 CLA.md 全部条款，特此签署。

- **Gitee 用户名**：
- **真实姓名**：
- **联系方式**：（手机号或邮箱，仅用于签署登记与身份确认）

我确认：我已阅读并理解 CLA.md 全部条款（含第 2 条许可授权、第 4 条版权归属），自愿签署。
```

### 步骤 3：等待核实登记

维护者核实后会将你登记到 [CLA-SIGNED.md](CLA-SIGNED.md) 名单并关闭 Issue。通常 1-2 天内完成；登记完成即签署生效。

### 步骤 4：提交 PR 时勾选声明

名单登记后，提交 PR 时在模板中勾选 **"CLA 声明"** 复选框即可，无需重复签署。

## 四、签署后你的权利与义务

| 类别 | 内容 |
|---|---|
| ✅ 保留 | 贡献的完整**版权**仍属于你，你对自己的贡献可**自行商用**或另行授权 |
| ✅ 授予 | 项目方获得 AGPL 授权 + **商业许可权**（闭源商业发行、贴牌等），支撑双许可模式 |
| ⚠️ 项目整体 | 你对**项目整体**（含他人贡献）的使用受主许可约束：遵守 AGPL 免费，闭源商用需项目方授权 |
| 📌 说明 | 第三方从仓库获取代码的权利由主许可 [LICENSE](LICENSE)（AGPL-3.0）约束 |

## 五、常见问题（FAQ）

**Q1：签署后我还拥有贡献的版权吗？**
拥有。CLA 授予的是许可而非版权转让，你始终是贡献的版权人。

**Q2：我的贡献以后会被闭源吗？**
有可能——你通过 CLA 第 2b 条授予了项目方商业许可权（含闭源商业发行），这正是双许可模式的基础；公众按 AGPL 使用（修改后的网络服务须开源）。你的贡献不会失去来源署名（CLA 第 7 条），版权也始终属于你。

**Q3：我对贡献内容还有哪些权利？**
你对**自己的贡献**拥有完整版权，可自行商用、修改、再授权，也可用于任何其他项目；但你对**项目整体**（含其他人的贡献）的使用受主许可约束——遵守 AGPL 免费，闭源商用需向项目方购买商业授权。

**Q4：我不签署会怎样？**
对应 PR 无法被合并——首次贡献必须完成签署，这是仓库的硬性要求。

**Q5：我的实名信息安全吗？**
仅用于签署登记与身份确认；若仓库将来转为公开，实名信息会先从名单移出另档保存（见 [CLA-SIGNED.md](CLA-SIGNED.md)）。

**Q6：签署后可以反悔吗？**
已授予的权利依 CLA 第 2 条为**永久且不可撤销**；你可以随时停止后续贡献，但不影响已生效部分。

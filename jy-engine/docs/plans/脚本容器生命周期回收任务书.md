# 脚本容器生命周期回收任务书

> 目标：脚本容器销毁（一次脚本运行结束）时，引擎**确定性回收**容器创建的跨层资源。设计与契约见 [../features/runtime/design.md](../features/runtime/design.md) / [contracts.md](../features/runtime/contracts.md)。
> 背景：cloud server 残留（脚本停止后 9300 仍监听）+ lSleep 锁泄漏（270172d 已修部分）暴露"资源回收无契约"的系统性缺口。

## 1. 范围

| 做 | 不做 |
|---|---|
| `ScriptContextLifecycleListener` 接口 + 广播链路（onStateChanged(kIdle, WORKER)） | 多容器并行（G 全局/图色单实例假设，见 design §6） |
| CloudService 首个接入（server 随容器回收，双通道：OnStop 快路径 + Java 兜底） | IDE 沙箱容器语义（调试态常驻，范围外） |
| 通用原则文档化（longjmp 跳析构铁律） | 其他服务（NetLib/VirtualDisplay...）接入——接口先行，分期迭代 |
| 脚本热更新 / 跨脚本共享 API | 正交能力，另行立项 |

## 3A. 补充修复（2026-09-21 晚，重复回包问题）

**现象**：连续两次运行后每条消息 dispatch N 次（回包/日志 N 份，observers 数逐轮 +1）。

**根因**：主引擎 LuaState **跨 execute 保留**（铁律 §3.5）——`cloud.onMessage` 注册的回调在 observers 表跨运行累积；OnStop 清空失效（函数首行 print 经 IdeLog 在 error 传播后抛错 → pcall 吞掉 → 清理整体未执行；io.open("/sdcard") proof 在 root FUSE 下同样失败，方法不适用）。

**修复**（CLOUD_LUA）：
- 注册改 **pending 暂存**：`onMessage` 进入 pendingObs；`run`/`recv` 时 **observers = pendingObs（整体替换）**——"本次运行会话的回调集合"语义，跨运行累积天然免疫
- OnStop 清理步骤**各自独立 pcall**（print 移出首行；诊断输出放最后）——终止钩子里任何语句抛错不得中断清理

**实测**：verify 2 轮 PASS + 重复回包检测（0.8s 二次 recv）无告警；连续运行 observers 恒 1。

**遗留**：①OnStop 内 `io.open("/sdcard")` 在 root FUSE 下失败（proof 方法不适用；OnStop 执行由 `server stopped (async)` 日志佐证）②FORTIFY `pthread_mutex_lock called on a destroyed mutex` 警告偶现（功能正常，疑似异步 stop 线程与 LuaContext destroy 竞态，待查）

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| listener 回调阻塞 loop 线程 | 契约强制异步（文档 + code review）；CloudCore 已示范异步模式 |
| 回调异常中断其他服务回收 | 逐个 try-catch，异常打日志 |
| 双通道（OnStop + listener）重复 stop | stop 幂等设计（server==null 直接 true）+ stopDone 门闩 |
| 后续服务接入遗漏 | 契约文档 + 新增 LocalService 的 code review checklist 项 |

## 1. 背景与目标

云控 WS 协议（9300）当前明文 JSON，抓包即可分析 op 面/任务数据。目标：**PSK 预共享密钥加密**，抓包只见密文；无 PSK 不影响功能（抓包者视角），客户拿密钥需反编译 APK（提高门槛；防反编译属后续字节码化层）。

约束（已核实引擎 CryptoLib 能力）：
- `crypt.aesCrypt(mode,key,data[,iv])`：E→Base64 密文 / D→UTF8 明文；key 16/24/32 字节 UTF8；iv 16 字节则 AES/CBC/PKCS5
- `sha256(str)`→hex、`encodeBase64/decodeBase64`；**无 GCM、无 HMAC**
- **关键坑**：CryptoLib 全链 String(UTF8) 往返——key/iv 必须用可打印 ASCII（随机二进制会损坏）。因此密钥/IV 均取 hex 串字符，密文走 Base64

## 2. 协议设计（加密帧 v1）

PSK = brand.json 的 `secret`（作者配置或 pack.py 自动生成的 64 hex 字符）。

密钥派生（两侧一致）：
```
encKey = sha256(psk .. "|enc1") 前 32 字符   -- 32 字节 AES-256 key（ASCII）
sigKey = sha256(psk .. "|sig1") 前 32 字符
```

帧格式（外层仍 JSON，客户端/服务端实现一致）：
```json
{"e":1, "iv":"<16位hex>", "d":"<明文JSON的AES-256-CBC密文Base64>", "s":"<sha256(sigKey|iv|d) 前16位hex>"}
```

加密（发送侧）：`iv` = 由 os.time + os.clock + 自增计数器拼接后取 hex 前 16 字符（可打印、每帧不同）；`plain` = 原始请求/响应 JSON 串；`ct = crypt.aesCrypt("E", encKey, plain, iv)`；`s = sha256(sigKey.."|"..iv.."|"..ct):sub(1,16)`。

接收侧：外层含 `"e":1` → 验 s → aesCrypt("D",...) → json.decode。任何失败回明文错误帧 `{"e":0,"err":"bad frame"}`（无信息泄漏）。

模式判定与兼容矩阵：
| 设备端(brand.json secret) | 客户端 | 行为 |
|---|---|---|
| 无 | 无 | 明文直通（现状，零回归） |
| 有 | 有（--secret 同值） | 全帧加密 |
| 有 | 无 | 收明文回 `{"e":0,"err":"encrypted"}`（客户端据此报错退出） |
| 无 | 有 | 客户端发加密帧被当未知帧，服务端回 `{"e":0,"err":"plaintext"}` |

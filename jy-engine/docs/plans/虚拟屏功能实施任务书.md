# 虚拟屏功能实施任务书

> 文档版本：v1.0（2026-09-18 新建，依据虚拟屏专项审查结论 + 无 root 前提拍板）
> 定位：虚拟屏（VirtualDisplay）方向全部开放项的实施任务书。优先级、对码与状态以 [../07-问题记录与遗留清单.md](../07-问题记录与遗留清单.md) §1 为准，本文档负责"怎么做"；完成后反向勾销 07。
> 前提拍板（2026-09-18）：**虚拟屏目标用户无 root**。root 链路（DisplayImplement / SurfaceControl 四件套）降为维护项（§6）；主战场 = 无 root 双引擎——① MediaProjection 图色桥接（地基，纯公开 API，§2）② Shizuku shell 身份多开后端（增量，§4/§5）。

## 2. 无 root 图色地基：SharedMemoryDisplay 桥接（P0）

- 现状：沙箱引擎 Builder 未设 Display → 回退 EmptyDisplay（`autolua2\engine\src\main\java\com\autolua\engine\core\AutoLuaEngineOnLocal.kt:464`、[engine-core/contracts.md](../features/engine-core/contracts.md) §Builder），findColor / saveScreen / getScreenFrame / ocr 全家空转（compat 报 "display unavailable"，`autolua2\engine\src\main\java\com\autolua\engine\extension\compat\CompatLib.kt:1409`）。而帧管线已就位：CaptureScreenService（MediaProjection + flags=17，`autolua2\engine\src\main\java\com\autolua\engine\display\projection\CaptureScreenService.java:65`）→ SharedMemoryManager seqlock A/B 双缓冲（[ipc/contracts.md](../features/ipc/contracts.md) §⑦）——缺的只是最后一桥。
- 方案：
  1. 新增 `SharedMemoryDisplay implements Display`（Java，`autolua2\engine\src\main\java\com\autolua\engine\extension\display\`）：`update()` 经 FrameBuffer seqlock 读协议取帧（ipc/contracts §⑦）；`getDisplayBuffer()` 返回 mmap DirectByteBuffer（复用 `SharedMemoryManager.mapFdToByteBuffer` native，`autolua2\engine\src\main\cpp\extension\SharedFrame.cpp:94-108`）；w/h/rowStride/pixelStride 取自 9 字节自描述头；
  2. 装配接线：app 沙箱 Builder `setDisplay(SharedMemoryDisplay)`——前置条件 = CaptureScreenService 已授权运行，未授权时仍回退 EmptyDisplay 并打点日志；root 引擎装配不变（`autolua2\engine\src\main\java\com\autolua\engine\core\root\Server.kt:141`）；
  3. **字节序对齐（设计关键）**：C++ Display.cpp 按"屏帧 BGRA/BGR"处理（`autolua2\engine\src\main\cpp\extension\Display.cpp:89-92`），而共享内存管线帧序按 RGBA 口径注释（`autolua2\engine\src\main\cpp\extension\VisionBridge.cpp:12-16`）——两链路字节序约定相反，桥接前必须实测 ImageReader 实际内存序，并在 SharedMemoryDisplay 或 Display.cpp 单点适配，取舍记录入 [../features/engine-core/design.md](../features/engine-core/design.md)；
  4. 读侧 TTL 独立：`FRAME_TTL_MS=1000`（`autolua2\engine\src\main\java\com\autolua\engine\display\projection\ScreenshotProviderManager.java:32`）面向 IDE 工具链；脚本热路径改用 frameCounter 变更检测（stale ≤1 帧），不复用大 TTL。
- 文档同步：engine-core/contracts.md §Builder 补 SharedMemoryDisplay 注入契约；ipc/contracts.md §⑦ 补"沙箱读侧"消费端条目；02-Lua-API规范.md 图色章逐函数标注适用运行模式（root / 沙箱）。
- 验收：无 root 模拟器（MediaProjection 已授权）下 findColor / findImageAll / saveScreen / getScreenFrame / ocr 全链路通过 [../05-构建与自测指南.md](../05-构建与自测指南.md) 全量自测；熄屏 / 未授权场景返回统一可读错误（不空转、不挂死）；root 全量自测无回归。

## 3. 权限无关缺陷修复（P0/P1）

### 3.1 update() 无帧挂死（P0）

- 现状：`imageMutex.wait()` 无超时（`autolua2\engine\src\main\java\com\autolua\engine\extension\display\DisplayImplement.java:190`），熄屏后镜像停发帧 → Lua update / getDisplayBuffer 永久阻塞；且 C++ Display 构造即 update（`autolua2\engine\src\main\cpp\extension\Display.cpp:59`），熄屏状态下引擎启动即卡。
- 方案：`wait(timeout)`（默认 3000ms，常量可配置）→ 超时返回旧帧或抛可读错误（"no frame: screen off?"）；§2 的 SharedMemoryDisplay 同规则（frameCounter 无变化超时同样处理）。
- 验收：熄屏后调用图色函数，脚本 3s 内收到可捕获错误并正常退出；留回归用例进 `autolua2\tools\selftest\`。

### 3.2 saveScreen jpeg 空 bug（P1）

- 现状：`_screenshot` 仅实现 kPng（`autolua2\engine\src\main\cpp\extension\Display.cpp:313-324`）；save() 把非 png 的 result=0 当成功 → 写 0 字节文件返回 true（Display.cpp:199-231）。
- 方案：短期——save() 对 kJpeg 显式返回 false 并提示仅支持 png；长期——jpeg 编码（仓库已有 3rd/libjpeg）按需求另行立项，不阻塞本任务书。
- 验收：`saveScreen(...,"jpeg")` 返回 false + 错误信息，不落 0 字节文件。

### 3.3 旋转自动跟随（P1）

- 现状：主链路仅暴露 isChangeDirection，transitMethod 向脚本抛 "display rotate"（`autolua2\engine\src\main\cpp\extension\Display.cpp:283-295`）；saveScreen 不走该包装（行为不一致）；对照 RootScreenshotProvider 已有完整轮询 + resize + 重建（`autolua2\engine\src\main\java\com\autolua\engine\display\projection\RootScreenshotProvider.java:356-397`）。
- 方案：DisplayImplement 内部自动重建（isChangeDirection → 引擎侧 localReset(0,0)，对齐 Display::screenshot 既有行为 Display.cpp:102-108），transitMethod 去抛错改为刷新后继续；`isChangeDirection` / `resetScreen` 公开 API 保留（02 不删，兼容老脚本）。
- 验收：横竖屏切换瞬间 findColor 不断流（容忍 ≤2 帧旧数据）、无脚本侧异常；saveScreen 与 findColor 行为一致。

## 4. Shizuku 虚拟屏多开后端（P1）

- 现状：引擎已有 Shizuku 注入通道（`autolua2\engine\src\main\java\com\autolua\engine\input\inject\ShizukuInjectorChannel.java`，注入降级链 C 位，01 §9.3）但仅覆盖输入；无建屏 / 拉起 / 按屏取帧能力。
- 方案（对齐懒人 virtualscreen 15 项语义，见 [API_GAP_LR](../features/luaapi/API_GAP_LR.md) §对齐表）：
  1. **建屏**：Shizuku UserService（app_process shell 身份）新增 IVirtualDisplayService——Android ≤14 `SurfaceControl.createDisplay` 反射（复用 `autolua2\engine\src\main\java\com\autolua\engine\conceal\SurfaceControlWrap.java:57-116` 四件套）+ setDisplayLayerStack/setDisplayProjection；Android 15+ 改 `DisplayControl.createVirtualDisplay` / `destroyVirtualDisplay` + `SurfaceControl.Transaction`（隐藏类反射，scrcpy 2.4+ 同款）；输出 Surface = ImageReader（RGBA_8888，15+ 强制，RGB_565 被拒）。**此双分支同时供 §6 root 链路复用，只写一份**；
  2. **拉起**：shell 身份 `am start --display <id>`（UserService 内 exec），或 ActivityOptions.setLaunchDisplayId 双路实测取优；
  3. **注入**：IInjectChannel 契约（[ipc/contracts.md](../features/ipc/contracts.md) §⑤）扩展 displayId 参数，Shizuku 通道事件携带 displayId 定向分屏；无障碍通道（降级链 D 位）不支持分屏注入——降级语义必须显式报错，禁止静默点错屏；
  4. **取帧**：该屏 ImageReader → SharedMemoryManager 多实例化（当前单例单屏，`autolua2\engine\src\main\java\com\autolua\engine\display\sharedmem\SharedMemoryManager.java` 需支持 per-display 缓冲命名与 fd 组）；
  5. **坐标**：displayId 绑定进 vd 对象，脚本坐标即虚拟屏坐标，引擎内完成 → 事件 displayId 映射，作者无感知。
- 明确限制（随 §5 写入 02）：虚拟屏内 App 无无障碍节点、无无障碍手势；感知仅图色 + OCR（含 ncnn-ocr 插件通道）。
- 验收：模拟器 root 环境 + 真机 Shizuku 环境各一；≥2 虚拟屏并行运行同款脚本互不串扰；主屏人工操作不受影响；主屏熄屏时虚拟屏内脚本可继续运行（虚拟屏独立合成的部分——实测记录入 07 已知限制）。

## 5. virtualDisplay Lua API 面（P1，先文档后实现）

- 分权动作（[../README.md](../README.md) §5A.1）：**先**改 [../02-Lua-API规范.md](../02-Lua-API规范.md) 新增 §virtualdisplay 章，**再**同步 [../features/luaapi/contracts.md](../features/luaapi/contracts.md) 映射总表与 [API_GAP_LR](../features/luaapi/API_GAP_LR.md) virtualscreen 行（:366，15 项逐项标注 等价 / 改名 / 不做），**然后**才按 §4 实现。
- API 形态（对象化，多开天然成立，坐标自动绑定各自的屏）：

```lua
local vd = virtualDisplay.create{ width = 720, height = 1280, dpi = 320 }
vd:runApp("com.xxx", "com.xxx.MainActivity")   -- shell am start --display
vd:tap(100, 200)                               -- 注入带 displayId
local x, y = vd:findImage("btn.png")           -- 帧源 = 该屏 ImageReader
vd:destroy()
```

- 三环境一致性（01 §8 铁律）：virtualDisplay 服务注册进 root 主引擎（Server.kt initEngine）/ IDE 沙箱（LuaEngineExecutor）/ 脚本调试三处；沙箱无 Shizuku 时 `create` 抛可读错误（引导授权），不静默。
- 验收：三环境 Lua 全局名一致；02 章含运行模式矩阵（无 root 无 Shizuku / 无 root + Shizuku / root）与"虚拟屏内无无障碍"限制声明；API_GAP_LR virtualscreen 批次记录可勾销。

## 6. root 链路维护项（P2）

1. **DisplayImplement Android 15+ 适配**：复用 §4.1 双分支（DisplayControl + Transaction），替换 SurfaceControl 四件套直调；IWindowManager 隐藏签名（getBaseDisplaySize 等）在 15/16 实测存续并补 fallback——当前失败静默 baseSize=(0,0) → ImageReader.newInstance(0,0) 抛异常难排查（`autolua2\engine\src\main\java\com\autolua\engine\conceal\IWindowManager.java:39-47`）；
2. **双 Provider 收敛**：DisplayImplement（直读）与 RootScreenshotProvider（共享内存）能力重叠，评估合并为单一建屏内核 + 两种消费端；旋转感知统一 DisplayManager.DisplayListener 替代 500ms 轮询（RootScreenshotProvider.java:466-490）；
3. **initialize 参数校验**：`width<=0 && height<=0` 的 `&&` 对单边 0 无防御（DisplayImplement.java:61），ImageReader.newInstance 抛异常路径需钳制。
- 验收：Android 14 模拟器回归 + Android 15 真机建屏成功；均过 05 全量自测。

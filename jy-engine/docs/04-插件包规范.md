# AutoLua 插件包规范（方案七 插件动态加载框架）

> 实现位置：`engine\src\main\java\com\autolua\engine\plugin\`（宿主接口 + PluginManager）、
> `engine\...\ide\PluginCommandHandler.java`（WS 命令）、示例插件 `plugins\demo-ocr\`。
> 路线对齐商业引擎（按键精灵插件市场）：dex/jar（DexClassLoader）+ so 按需加载，OCR 为第一个目标插件类型。

## 1. 插件包格式

插件包为标准 zip（`plugin.zip`），布局：

```
plugin.zip
├── manifest.json                # 必需：插件清单（见 §2）
├── classes.jar                  # 必需二选一：含 classes.dex 的 jar（DexClassLoader 原生支持）
├── classes.dex                  #   或裸 dex；查找顺序 classes.jar → classes.dex
└── lib/<abi>/*.so               # 可选：native 库，<abi> ∈ 支持的 ABI 名
    ├── arm64-v8a/libxxx.so
    ├── armeabi-v7a/libxxx.so
    └── ...
```

宿主安装后落盘布局（app 私有目录，进程外不可读）：

```
getDir("plugins")/<pluginId>/<version>/          # classes.jar|classes.dex + manifest.json 副本
getDir("plugin_libs")/<pluginId>/*.so            # 命中 ABI 的 so 平铺
getDir("plugin_data")/<pluginId>/                # 插件私有数据目录（IPluginContext.getPluginDir）
getCodeCacheDir()/                               # DexClassLoader odex 输出
cache/ide_plugin_push/<name>.zip(.tmp)           # WS 推送临时文件（安装成功后删除）
cache/asset_plugin_install/<name>.zip            # assets 预置插件安装临时拷贝（装完即删）
/sdcard/Android/data/com.autolua.autolua2/files/plugins/    # 外部免权限插件投放目录（见 §11）
```

## 2. manifest.json 字段定义（PluginMeta）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 插件 id，如 `com.autolua.plugin.ocr.demo`；仅允许 `[A-Za-z0-9._-]` 且不得含 `..`（防路径穿越） |
| `name` | string |  | 显示名 |
| `version` | string | ✅ | 版本号，如 `1.0.0`；作为版本目录名，同 id 多版本按数值比较取最高 |
| `mainClass` | string | ✅ | 入口类全限定名，必须实现 `com.autolua.engine.plugin.IPlugin` |
| `provides` | string[] | 建议 | 能力标签，如 `["ocr"]`；宿主按标签路由（ocr → IOcrPlugin） |
| `minHostVersion` | string |  | 最低宿主版本要求（当前框架未校验，预留） |
| `sha256` | string | ✅ | **内容清单 hash**（hex 小写，见 §3）；安装时强校验 |

## 3. sha256 内容清单计算规则

`manifest.json` 的 `sha256` 字段是对**包内容**的确定性摘要，与 zip 文件本身的字节无关
（重打包/时间戳差异不影响校验）：

1. 取 zip 内**除 `manifest.json` 外**的全部 file entry（跳过目录 entry）；
2. 按 entry 名（`FullName`，`/` 分隔）**升序排序**；
3. 逐条计算 entry **未压缩内容**的 sha256（hex 小写），串接为一行：
   `<name>:<未压缩size>:<entry的sha256hex>`
4. 每行以 `\n` 结尾，全部行串接成"清单文本"（UTF-8）；
5. 对**清单文本整体**做 sha256（hex 小写）→ 填入 manifest.json 的 `sha256`。

伪代码：

```
lines = for entry in zip.fileEntries(exclude="manifest.json").sortedByName():
          entrySha = sha256_hex(entry.uncompressedBytes)
          yield entry.name + ":" + entry.size + ":" + entrySha
manifest.sha256 = sha256_hex(utf8(join(lines, "\n") + "\n"))
```

校验失败回包会带上宿主计算值：`manifest sha256 mismatch: manifest=..., computed=...`，
打包方直接回填 `computed` 即可。文件级完整性另有保障：WS 推送时 `plugin_push_start` 携带
**整包 zip 文件的 sha256**，`plugin_push_complete` 时先校验文件级 sha256，再做内容清单校验。

## 4. ABI 匹配规则

- 按 `Build.SUPPORTED_ABIS` **优先级顺序**（首选 ABI 在前）逐个匹配包内 `lib/<abi>/`；
- 取**第一个命中的 ABI** 的全部 `*.so` 解压到 so 根目录（平铺，只保留文件名）；
- 包内不含 `lib/` → 合法（纯 dex 插件，`so=0`）；
- 包内含 `lib/` 但无一 ABI 命中 → 安装失败（`SecurityException`，so 在该设备不可运行）。

## 5. so 交付模型（Android 9+ 兼容）

Android 9+ 禁止 `System.load` apk/zip 内的 so，故采用**宿主解压 + 插件主动加载**：

1. 宿主安装时把命中 ABI 的 so 解压到 `getDir("plugin_libs")/<pluginId>/`；
2. `DexClassLoader(dexPath, codeCacheDir, librarySearchPath, parentClassLoader)` 的
   librarySearchPath = **宿主 nativeLibraryDir 优先 + so 根目录**（宿主目录优先是
   x86_64 转译模拟器适配：Android 9 + libnb 转译层对 app 私有目录 so 存在 JNI 绑定
   异常；把插件 so 预置进宿主 APK jniLibs 后模拟器经该路径正常绑定。真机宿主内无
   同名 so → 自然命中 so 根目录内 zip 解压产物，自包含语义不变）；
3. **插件加载 so 必须经自身 classloader**（在插件代码里直接 `System.loadLibrary("xxx")`，
   失败回落 `System.load(ctx.getNativeLibraryDir()/libxxx.so)` 绝对路径）：
   **ART 按类加载器匹配 native 方法所属库**——`ctx.loadNativeLibrary` 的
   `System.load` 调用方是宿主类，库注册到 app classloader，插件类（DexClassLoader）
   的 native 方法绑定不到（实测 `No implementation found`）。
   `ctx.loadNativeLibrary` 保留用于"纯资源型 so"或宿主已注册、仅需共享符号的场景；
4. `loadNativeLibrary` 传含路径分隔符的参数时按绝对路径加载（so 必须已落在 app 私有目录内）；
5. **同一 so 只能属一个类加载器**（ART 硬限制）：同进程多实例（loadAll 重载 + 覆盖
   安装并存）时第二个实例加载同路径 so 会 ULE，插件应按 3 的顺序回落到未被占用的
   路径（见 NcnnOcrPlugin.onInit 的两级加载实现）。

## 6. 生命周期

| 阶段 | 触发 | 行为 |
|---|---|---|
| 安装 | WS `plugin_push_complete`（或进程内 `PluginManager.install`） | sha256 校验 → 解压到**暂存目录**（dex: `<version>.tmp`；so: `<id>.so.tmp`）→ DexClassLoader → 反射实例化 → **onInit**（异常则回滚，只删暂存目录，旧安装无损）→ onInit 成功后 **rename 原子转正**。暂存目录对 `loadAll` 不可见，并发进程（root 注入进程）看不到半成品安装态 |
| 版本覆盖（本进程无运行实例） | 同/新版本 install | onInit 成功后：旧 versionDir/soDir 先改名 `.old`（rename 失败可恢复）→ 暂存 rename 转正 → 新实例注册 + 旧实例 **onRelease** + `.old` 目录 try-delete（被 mmap 删不掉属正常，容忍失败） |
| 版本覆盖（本进程已有运行实例） | 同/新版本 install | **仅落盘不热重载**：包内容落盘交换后运行实例保持不变（native so 不可卸载，且静态链入的运行时如 libomp 不允许进程内多副本——热加载第二份 so 副本会 `__kmp_fatal` SIGABRT），新版本**进程重启后由 loadAll 生效** |
| 卸载 | WS `plugin_remove` / `uninstall(id)` | **onRelease** → 移表 → 版本目录/so 目录/数据目录 try-delete |
| 进程重启 | app 层 `PluginManager.loadAll()`（root 引擎进程在 Server 构建 + 每次 run_script 前幂等刷新） | 扫描安装根目录（跳过 `.tmp`/`.old`），逐插件取最高版本目录重载（不再做内容清单校验，安装时已验过）；失败跳过并记日志，不影响其余插件 |

生命周期接口（`IPlugin`）：

```java
void onInit(IPluginContext ctx) throws Exception;  // 加载 so、初始化模型；抛异常=安装失败
void onRelease();                                   // 卸载/覆盖前调；宿主容忍异常
String getId();                                     // "com.autolua.plugin.ocr"
String getVersion();                                // "1.0.0"
String[] getProvides();                             // {"ocr"}
```

## 7. 接口契约完整签名

```java
package com.autolua.engine.plugin;

public interface IPlugin {
    void onInit(IPluginContext ctx) throws Exception;
    void onRelease();
    String getId();
    String getVersion();
    String[] getProvides();
}

public interface IPluginContext {
    byte[] captureScreen(int x, int y, int w, int h);   // RGBA 帧裁剪，无帧返回 null
    byte[] captureFull();                               // 整帧 RGBA
    File getPluginDir();                                // 插件私有数据目录
    void log(String msg);
    void log(String tag, String msg);
    String getAbi();                                    // Build.SUPPORTED_ABIS[0]
    boolean loadNativeLibrary(String soNameOrPath);     // System.load 绝对路径；失败 false+日志
}

public interface IOcrPlugin extends IPlugin {
    // RGBA 帧内识别文字；rect 为识别区域（帧内坐标，整帧原点=屏幕原点）
    // 返回文本块列表（坐标帧内坐标）；无文字回空列表，异常宿主转 ocr plugin error
    List<OcrTextBlock> recognize(byte[] frame, int frameW, int frameH,
                                 int rectX, int rectY, int rectW, int rectH) throws Exception;
}

public class OcrTextBlock {   // gson 兼容 POJO
    public String text; public int x, y, w, h; public float confidence; // confidence 0~1
}
```

日志 tag：`AutoLuaPlugin:<id>`（`log(tag,msg)` 为 `AutoLuaPlugin:<id>:<tag>`）。

## 8. WS 命令（wscat 可复制的 JSON 序列）

连接 `ws://<设备IP>:8080`（8080 占用自动回退 8081..8085）。回包统一
`{"type":"plugin_result","data":{...}}`；错误回 `{"type":"error","data":{"msg":"..."}}`。

```
// ① 开始推送（sha256 = 整包 zip 文件的 sha256；totalChunks 分块数）
{"type":"plugin_push_start","data":{"name":"demo-ocr","totalChunks":2,"totalSize":12345,"sha256":"<zip文件sha256>"}}

// ② 逐块推送（index 从 1 起严格顺序；data = base64(分块字节)；静默不回包）
{"type":"plugin_push_chunk","data":{"name":"demo-ocr","index":1,"data":"<base64...>"}}
{"type":"plugin_push_chunk","data":{"name":"demo-ocr","index":2,"data":"<base64...>"}}

// ③ 完成：文件级 sha256 校验 → PluginManager.install（内容清单 sha256 再验）→ 安装
{"type":"plugin_push_complete","data":{"name":"demo-ocr"}}
// 回包：{"type":"plugin_result","data":{"installed":true,"id":"com.autolua.plugin.ocr.demo","version":"1.0.0","provides":["ocr"]}}

// ④ 查询已安装插件
{"type":"plugin_list"}
// 回包：{"type":"plugin_result","data":{"plugins":[{"id":"com.autolua.plugin.ocr.demo","version":"1.0.0","provides":["ocr"]}]}}

// ⑤ 能力协商（vision.ocr 动态 + plugins 字段）
{"type":"capabilities"}

// ⑥ OCR 识别（rect 可选，绝对屏幕坐标；需截图通道已启动）
{"type":"ocr","data":{}}
{"type":"ocr","data":{"rect":{"x":0,"y":0,"w":1080,"h":2340}}}
// 回包：{"type":"result","data":{"results":[{"text":"DEMO","x":500,"y":1158,"w":80,"h":24,"confidence":0.95}],"text":"DEMO"}}

// ⑦ 卸载
{"type":"plugin_remove","data":{"id":"com.autolua.plugin.ocr.demo"}}
// 回包：{"type":"plugin_result","data":{"removed":true,"id":"com.autolua.plugin.ocr.demo"}}
```

错误语义：无 OCR 插件时 `ocr` 回 `__ERROR:ocr not available in this engine version`；
插件 `recognize` 抛错回 `__ERROR:ocr plugin error: <原因>`；
sha256 不一致/缺字段/ABI 不匹配等安装失败回 error（消息含计算值便于回填）。

## 9. 安全模型

**现状：**

1. **文件级完整性**：`plugin_push_start.sha256`（整包 zip 文件 sha256）在 complete 时校验，
   防传输损坏/篡改；
2. **内容清单校验**：manifest.sha256（§3 内容清单 hash）安装时强校验，任何 entry 被替换
   （包括 classes.dex 和 so）都会失配拒绝——需要重打包即需要重算 manifest，
   因此 manifest 无法被独立篡改；
3. **路径安全**：id/version 白名单 `[A-Za-z0-9._-]`（拒绝 `..`），so 解压固定三段结构平铺；
4. **运行隔离**：插件运行于宿主进程（DexClassLoader，parent = engine classloader），
   能力面收敛到 IPluginContext（截图帧/私有目录/日志/ABI/so 加载），无 Context/文件系统全权。

**已知边界（与按键精灵插件市场同级别的"作者可信"模型）**：当前无签名校验，
掌握 WS 通道（局域网内）且能构造合法 manifest 的推送方即可安装任意代码插件。

**预留扩展点（服务端签名体系）**：

- `PluginMeta.minHostVersion` 已预留未校验；
- manifest 可平滑扩展字段（gson 忽略未知字段）：预留 `signature`（对 §3 清单文本或
  manifest 规范化 JSON 的 RSA/ECDSA 签名）+ `certId`（宿主内置公钥表），
  安装流程在"内容清单校验"后插入"验签"步骤即可，包格式不变；
- 插件市场分发时由服务端持有私钥对包签名，宿主只信内置公钥，实现"仅市场签名包可装"。

## 10. DemoOcrPlugin 全链路验证步骤

1. **编译插件**：见 `plugins/demo-ocr/README.md`（javac + d8 → classes.dex）；
2. **打 zip**：`manifest.json + classes.dex`（sha256 回填见 README 的 PowerShell 函数）；
3. **推送安装**：§8 的 ①②③ 序列（脚本按 64KB 分块 base64 循环发 chunk）；
4. **确认安装**：回包 `installed:true`；logcat 过滤 `AutoLuaPlugin` 可见
   `demo ocr onInit, abi=arm64-v8a` 与 `loadNativeLibrary(libdemo) -> false`（预期，无 so）；
5. **能力协商**：`{"type":"capabilities"}` → `vision.ocr:true`、
   `plugins:[{id:"com.autolua.plugin.ocr.demo",...}]`；
6. **OCR 调用**：`{"type":"ocr","data":{}}` → `results:[{text:"DEMO",...}]`、`text:"DEMO"`；
   logcat 可见 `recognize: frame ...`（帧通路验证）；
7. **持久化**：重启 app → `loadAll` 日志 `plugin reloaded` → `plugin_list` 仍在；
8. **卸载**：§8 ⑦ → `removed:true` → `capabilities` 的 `vision.ocr` 回 `false`；
9. **版本覆盖**（可选）：改 `version` 重打包再装 → 旧实例 onRelease 日志、`plugin_list` 版本更新。

## 11. 本地安装（免服务端）

无需任何服务端/插件市场，插件包本地即可用。三种安装方式（可并存，安装逻辑同为 `PluginManager.install`，
sha256 内容清单校验 → 解压 → DexClassLoader → onInit 全流程一致）：

### 方式一：assets 预置（开箱即用）

APK 自带插件包：`app/src/main/assets/plugins/*.zip`（当前预置 `demo-ocr.zip`）。
app 启动时 `PluginManager.installFromAssets()` 自动安装：

- 遍历 assets 的 `plugins/` 下所有 `.zip` → 复制到 `cache/asset_plugin_install/<name>` → `install`（临时目录用完即删）；
- **防重复（幂等）**：安装前解析包内 manifest 的 `id`+`version`，与已安装表比对，
  同 id 同版本已装则跳过；版本目录存在但加载失败时不会被跳过——覆盖式重装可自愈；
  同 id 新版本则覆盖升级。

### 方式二：外部目录放 zip（免存储权限，推荐分发方式）

把插件 zip 放到应用专属外部目录，app 启动时 `PluginManager.installFromExternalDir()` 自动扫描安装：

```
/sdcard/Android/data/com.autolua.autolua2/files/plugins/    # getExternalFilesDir(null)/plugins/
```

adb 投放（无需 root、无需存储权限）：

```bash
adb push demo-ocr-1.0.0.zip /sdcard/Android/data/com.autolua.autolua2/files/plugins/
```

处理行为（启动时自动完成）：

- 安装成功 → zip 移入 `plugins/processed/` 归档（防下次启动重复安装）；
- 安装失败 → zip 移入 `plugins/failed/`，logcat 过滤 `AutoLuaPlugin` 查看原因；
- 归档移动失败时退化为原地改名加后缀（`.installed` / `.failed`），再失败仅记日志跳过——
  install 为覆盖式重装，极端场景下即使重复安装结果也一致；
- 幂等：已归档/已改名的 zip 不会再被扫描；同 id 同版本重复放置结果一致，新版本覆盖升级。

### 方式三：WS plugin_push 三段推送（IDE/远程联调）

见 §8：`plugin_push_start` → `plugin_push_chunk`（分块 base64）→ `plugin_push_complete`，
文件级 sha256 + 内容清单 sha256 双重校验。

### 启动时序

`MainApp.onCreate`：`loadAll()`（恢复已装插件）→ 后台协程 `installFromAssets()` →
`installFromExternalDir()`。三种方式安装落盘后均持久，进程重启由 `loadAll()` 恢复。

## 12. Lua 脚本调用口（0bf13cb 批次新增）

插件运行时在 Lua 侧的入口，均注册于 **Lua 所在进程本地**（root 引擎进程由 Server.kt
注入宿主插件目录 override 后 `loadAll()`；沙箱由 MainApp 注册）：

### 12.1 plugin 表（生命周期，派大星对齐）

```lua
plugin.list()            -- {{id=, name=, version=, provides={...}, loaded=bool}, ...}
plugin.getLoaded()       -- { [id] = true, ... }
plugin.load("com.x.y")   -- 加载已安装未加载插件（取最高版本），bool
plugin.unload("com.x.y") -- 卸出（onRelease + 移表，目录保留），bool
plugin.loadAll()         -- 重载全部
plugin.install("/path/x.zip")  -- 本地直装（sha256 校验同 WS 通道），bool, err
plugin.uninstall("com.x.y")    -- 卸载（onRelease + 删目录），bool
plugin.getPluginPath(id) -- dex/jar 所在版本目录
plugin.getSoPath(id)     -- so 根目录（app_plugin_libs/<id>）
```

### 12.2 ocr 表（OCR 插件运行时）

```lua
ocr.isSupported()             -- 是否安装 provides=["ocr"] 且实现 IOcrPlugin 的插件
ocr.list()                    -- 已安装 OCR 插件 id 数组（多 OCR 共存）
ocr.use("com.x.ocr2")         -- 切换激活插件 → bool；ocr.use() 恢复默认（第一个注册的）
ocr.active()                  -- 当前生效插件 id（无插件为 nil）
ocr.ocrText(0, 0, 719, 1279)  -- 区域识别 → 文本（多块 \n 拼接，走当前生效插件）
ocr.ocrEx(0, 0, 719, 1279)    -- → {{text=,x=,y=,w=,h=,confidence=},...}
ocr.ocrExNew(...)             -- 块坐标相对基点（懒人形态）
ocr.recognizeFile("/path/x.png")  -- 文件直识（调试用）
```

多 OCR 共存（路线A 门面+切换）：识别类接口统一走"当前生效"插件——显式
`ocr.use(id)` 优先，未切换取第一个注册的；切换为进程内存态（app 进程与 root
进程各一套，各插件 native 推理会话独立、互不干扰），无需重启引擎；
IDE WS `ocr` 命令与脚本共用同一激活选择（`PluginManager.getOcrPlugin()`）。

取帧链路：compat 的 ocrText 经 `getScreenFrame()`（Display 同源帧，RGBA）→
`OcrLib.recognizeRaw`（行 stride 重排为契约要求的紧凑 frameW*4/行）→ 插件 recognize。
帧数据 ~3.7MB 超 Binder 1MB 限制，故 **root 进程本地加载插件**，不走跨进程。

### 12.3 插件 Lua API 贡献（P1 批次新增：插件自定义全局）

插件可实现 `com.autolua.engine.base.LuaEnvContributor`（引擎内置接口，插件 dex 经
parent classloader 可见），引擎在建 LuaContext 时回调 `contribute(ctx)`，
插件经 `PluginLuaHelper.putGlobal(ctx, name, api, iface)` 把普通 Java 对象注册为
Lua 全局表（JavaObjectWrapper 反射桥接，与 http/file 等内置服务同链路）。

```java
public class XxxPlugin implements IPlugin, LuaEnvContributor {
    @Override
    public void contribute(LuaContext lua) {
        PluginLuaHelper.INSTANCE.putGlobal(lua, "xxx", new Api(ctx), Api.class);
    }
}
```

```lua
xxx.anyMethod(1, "a")   -- 脚本直接调用插件定义的函数
```

接线点（引擎内已完成，无需插件关心）：
- root 主引擎：`AutoLuaEngineOnLocal.pushLocalServices` 末尾 → `PluginManager.contributeLua(ctx)`（每个新建 LuaContext 触发）；
- IDE 沙箱：app 启动 loadAll/直装后 `LuaEngineExecutor.contributePlugins()`。

语义注意：
- 贡献时机 = LuaContext 创建时；**后装插件需重建 context**（主引擎重启 / 沙箱重跑
  启动流程）后全局才出现；
- root 主引擎 LuaContext 长生命周期（state 跨 execute 保留），装贡献型插件后需
  重启引擎进程；
- 单插件贡献失败只记日志（logcat `AutoLuaPlugin`），不影响其余插件与 context 创建；
- 注册名勿与内置服务冲突（http/file/device/crypt/app/compat/plugin/ocr...）。

活体案例：`plugins\demo-luaapi\`（安装后脚本可调 `plugindemo.hello("x")` 等 4 个
方法，覆盖字符串/数字/表参数桥接）。

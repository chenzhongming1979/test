# 构建与自测指南

> 文档版本：v1.0（2026-09-14）
> 环境：Windows + Android Studio 工具链。全部命令在 `autolua2\` 根执行。

## 1. 环境要求

| 项 | 版本 | 说明 |
|---|---|---|
| JDK | 17 | AGP 8.5 要求 |
| AGP / Kotlin | 8.5.0 / 1.9.0 | 见 gradle\libs.versions.toml |
| NDK | **25.2.9519653** | engine\build.gradle.kts 固定 |
| CMake | **3.22.1** | 同上 |
| protoc | 25.3 | preBuild 按 OS 自动下载（见 §5 坑①） |
| MLN Lite | 1.0.0 aar | app preBuild 从 GitHub release 下载解到 libs\（`-x downloadMLN` 可跳过，需已有缓存） |
| Node | ≥18 | tools\selftest 自测运行器（依赖 vscode-plugin\node_modules\ws） |
| 模拟器/真机 | 已 root（引擎全量能力需 uid 0） | MuMu/雷电等均可 |

子模块（6 个，`engine\src\main\cpp\3rd\`）：lua(5.4) / cjson / libhv / libjpeg-turbo / protobuf / autolua_vision。
克隆后需 `git submodule update --init --recursive`。git 全局代理常不在线时可 `git -c http.proxy= -c https.proxy= ...` 临时绕过。

## 2. 日常构建

```powershell
# 推荐：带 exit code 与 APK 时间戳回显（输出重定向 autolua2\build\）
powershell -File tools\build_app.ps1

# 等价手动命令
.\gradlew.bat :app:assembleDebug -x downloadMLN
```

- 产物：`app\build\outputs\apk\debug\autolua2_<ver>.apk`。
- **tools\build_app.ps1 的重定向目录 autolua2\build 不存在会静默失败**（APK 时间戳是旧的）——先确保 `autolua2\build\` 存在。
- Release：`.\gradlew.bat :app:assembleRelease`（4 ABI 全量约 8-9 分钟；签名走 app\build.gradle.kts 的 config.properties 可选配置 + autolua2.keystore）。
- JNI 符号抽查：`powershell -File tools\check_so.ps1`（验 libengine.so 是否含 SharedFrame/VisionBridge 导出）。

## 3. 模拟器联调（标准流程）

```powershell
# 1) 安装（Streamed Install 卡住就加 --no-streaming）
adb uninstall com.autolua.autolua2
adb install --no-streaming app\build\outputs\apk\debug\autolua2_x.x.x.apk

# 2) 免 UI 开启无障碍
adb shell settings put secure enabled_accessibility_services com.autolua.autolua2/com.autolua.engine.accessibility.AutoLuaAccessibilityService
adb shell settings put secure accessibility_enabled 1

# 3) 清残留 root daemon（杀过引擎/重装后必做，否则占 UiAutomation 注册位 → 节点域全 FAIL 且 err 为空）
adb shell su -c "for p in $(ps -A -o PID,NAME | grep app_process64 | awk '{print $1}'); do kill $p; done"

# 4) 启动 app，等待 root 引擎就绪（logcat 过滤 AutoLuaEngineClient 出现 ENGINE RUNNING）
adb shell am start -n com.autolua.autolua2/.activity.SplashActivity

# 5) 端口转发
adb forward tcp:19080 tcp:8080
```

## 4. 全量自测

```powershell
cd tools\selftest
node run_remote.js        # 推 main.lua → run_script → 收 log → selftest_run.log
```

- `selftest\main.lua` 按 input/app/net/sys/node 域开关分组，PASS/FAIL 汇总落 `_selftest/result.txt`。节点域含选择器条件/等待轮询/树遍历几何/NodeLib（getNodeXml/saveNode/findByIndex/setNodeMode）用例；closeAccessibility 仅验存在不实际调用（会关掉无障碍影响后续用例）。
- 参考基线：**PASS=442 FAIL=0**（2026-09-14，提交 5cd1ff4；4 个 ime 环境项在无 IME 授权环境算预期 FAIL）。
- 单项诊断：`run_diag.js`（默认推 diag_ime.lua）；金丝雀/二分：probe_min/probe14/bisect.lua。
- Toast 验证：`node tools\run_toast_test.mjs`；点击压测：`tools\click_stress.mjs`；H264 流分析：`tools\h264_probe.mjs`。
- 浏览器控制台：直接打开 `tools\remote.html`（WS 直连 ws://<设备IP>:8080 或经 forward）。

## 5. 工具链已知坑（按踩坑频率排序）

1. **protoc 下载超时**：gradle clean 会删 `engine\build\protoc` 缓存，downloadProtoc 走 GitHub 直链常超时。解法：用镜像 `https://ghfast.top/https://github.com/protocolbuffers/protobuf/releases/...` 手动下载 protoc-25.3-win32.zip 放 `engine\build\protoc.zip`（Download task `overwrite=false` 会自动跳过）。
2. **Gradle VFS 不感知 IDE 外部改动**：用编辑器直接改源码后构建报旧错误 → `.\gradlew.bat clean` 或 `--no-build-cache`。
3. **Ninja 缓存陈旧**：头文件报"幽灵编译错误"（磁盘文件正确但报旧行号）→ 删 `engine\.cxx` 重新构建。
4. **CMake glob 不触发 reconfigure**：`aux_source_directory` 新增源文件不重配 → 随便改一下对应 CMakeLists.txt（加注释行）再构建。
5. **whole-archive**：extension 静态库内 JNI 导出无 C++ 调用者会被链接器丢弃（UnsatisfiedLinkError）→ 已用 `-Wl,--whole-archive` 固定，新加 JNI 导出的文件放 extension 时无需额外处理，放其他 STATIC 库则要确认有引用。
6. **子模块提交**：改 `3rd\autolua_vision`、libhv 等子模块文件 → 进子模块先 commit（detached HEAD 时 `git branch -f main HEAD && git checkout main` 修正）→ 回主仓库 `git add <子模块目录>` 更新 gitlink。**嵌套 .git 的 vendored 目录会被 add 成 gitlink**（libjpeg 当年踩过：先删 .git 再 add）。
7. **PS5 限制**：不支持 heredoc（git commit 用多个 -m）；ClientWebSocket 走系统代理连不上本机 forward（WS 测试一律用 node）；`Set-Content` 正则替换会损坏 UTF-8 中文注释（批量改文件用编辑器，不用 PS 正则）。
8. **APK 体积**：libhv 全量静态链入后 APK ~184MB（163MB→184MB），后续可裁剪。

## 6. 提交规范

- 仓库无全局 git 身份时：`git -c user.name="TRAE" -c user.email="git@mail.trae.cn" commit`（与历史一致）。
- 提交信息风格：`feat: <域>——<要点>` / `fix: <域>: <问题>` / `docs: <范围>`，批次功能一提（参考 git log）。
- 交付验证通过后即提交（含 docs 同步）；构建日志/临时产物不入库（见 .gitignore）。

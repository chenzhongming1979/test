## 1. 项目定位

autolua2 是一个 **Android 自动化脚本引擎框架**：用 Lua 编写脚本，引擎提供图色识别、触控注入、无障碍节点操作、设备/应用控制、网络/数据库等能力，配套 VSCode 插件实现远程开发调试（推文件 → 运行 → 日志回传 → 投屏操控）。

- **双执行模式**：root 引擎（app_process 独立进程，uid 0，能力全量）与 IDE 沙箱（app 进程内 LuaEngineExecutor，联调用）。
- **商业引擎对齐**：API 命名与《懒人精灵》《派大星(FireFly)》对齐（迁移友好），对标分析见 [features/luaapi/API_GAP_LR.md](features/luaapi/API_GAP_LR.md) / [features/luaapi/API_GAP_FIREFLY.md](features/luaapi/API_GAP_FIREFLY.md)。
- **脚本 API 权威手册**：[02-Lua-API规范.md](02-Lua-API规范.md)（18+ 章，全部签名从源码核实）。

## 2. 仓库地图

```

├── engine\                      # :engine Android Library —— 引擎本体（Java/Kotlin + C++）
│   └── src\main\
│       ├── cpp\                 # C++ 引擎（base/core/extension/remote + 3rd\）
│       │   └── 3rd\             # 6 个 git 子模块：lua/cjson/libhv/libjpeg/protobuf/autolua_vision
│       ├── java\com\autolua\engine\   # Java 桥接层（base/core/conceal/display/accessibility/
│       │                              #   input/inputmethod/ide/plugin/extension.*）
│       ├── aidl\                # IScreenShareService / IAuxDumpService / IInjectorService 等
│       └── proto\               # interaction.proto / Authorization.proto（remote 层消息）
├── app\                         # :app Android 应用 —— 客户端宿主（com.autolua.autolua2）
│   └── src\main\
│       ├── java\com\autolua\autolua2\ # MainApp/MainService/activity/mln/keepalive/project/...
│       ├── aidl\                # IMainService / IInputMethodService（app 进程间）
│       └── assets\              # plugins\demo-ocr.zip（预置插件）、hotreload.lua
├── vscode-plugin\               # VSCode 插件 autolua-vscode（TypeScript + esbuild + ws）
├── plugins\demo-ocr\            # OCR 插件示例（源码 + 打包工具 + 产物 zip）
├── tools\                       # 构建/自测/联调脚本（build_app.ps1、selftest\、remote.html）
└── docs\                        # 本文档体系
```

要点：
- `:engine` 是能力层，`:app` 是装配层——**所有服务注入有三处注册点**（root 进程 Server.kt / app 进程 Client.Builder / IDE 沙箱 LuaEngineExecutor），见 §8。
- `plugins\` 不参与 Gradle 构建；`tools\` 也不参与。

```

│                                                                    │
│  [app 主进程] com.autolua.autolua2                                  │
│   ├ MainApp（装配：MLN/悬浮球/IDE WS 服务/插件安装/引擎创建器）         │
│   ├ MainService（前台常驻，WakeLock，AIDL IMainService）             │
│   ├ IdeServerManager（IDE WebSocket 8080..8085 + UDP 发现）          │
│   ├ LuaEngineExecutor（IDE 沙箱 Lua state）                         │
│   ├ CaptureScreenService（MediaProjection 前台采集，engine 模块）     │
│   ├ AutoLuaAccessibilityService（无障碍：手势/节点 dump/自拉活）      │
│   ├ AutoLuaInputMethodService（自研 IME，独立进程可配）              │
│   └ AuxDumpService（IAuxDumpService，与无障碍同进程）                │
│        │  stdio Parcel Transporter（RootProcessStarter 拉起）        │
│        ▼                                                            │
│  [root 引擎进程] app_process（uid 0）                                │
│   ├ Server.kt initEngine → AutoLuaEngineOnLocal（root 模式）        │
│   ├ AutoLuaEngineService（C++ 引擎编排 + LuaInterpreter worker）     │
│   ├ DisplayImplement（截图：共享内存 seqlock 帧）                    │
│   ├ RootScreenshotProvider（root 免授权截屏，运行在 app 进程则经      │
│   │    IScreenShareService AIDL 传 fd）                              │
│   └ 全量 14 域 Java 服务（§8 注入矩阵）                              │
│        │  stdin/stdout 行协议                                        │
│        ▼                                                            │
│  [root 注入子进程] app_process（RootInputInjectorMain，通道 B）      │
│                                                                    │
│  [PC] VSCode 插件 / remote.html ── WS ws://ip:8080..8085 ──┘        │
│       （adb 场景经 adb forward tcp:xxxx）                           │
└────────────────────────────────────────────────────────────────────┘
```

进程间通讯一览：

| 链路 | 机制 | 代码位置 |
|---|---|---|
| app ↔ root 引擎 | stdio Parcel 序列化（Transporter），方法名分发，返回必须 Unit | engine\core\root\{Server,Client,TransportImp,RootProcessStarter} |
| app ↔ 采集服务 | AIDL IScreenShareService（共享内存 fd 经 FileDescriptor dup） | engine\...\display\projection\ScreenShareServiceImpl |
| app/引擎 ↔ 无障碍 dump | AIDL IAuxDumpService（PFD 流式返回整树 XML/Bundle） | engine\...\accessibility\AuxDumpService* |
| 引擎 ↔ 注入子进程 | stdin/stdout 行协议（down/move/up/tap/swipe/...） | engine\...\input\inject\RootInjectorChannel |
| app ↔ IME | 广播 → InputConnection 注入文本/键码 | engine\...\inputmethod\{AutoLuaInputMethodService,ImeApi}；root 侧由 ImeLib 用 shell settings/am 直控 |
| PC ↔ 设备 | WebSocket JSON 帧（§协议文档）+ 二进制流帧 | engine\...\ide\* |
| 脚本 print → IDE | root 进程 IdeLog 跨进程代理 → IdeServerManager → WS `log` 帧 | app\...\IdeLogService.kt |
| 宿主事件 → Lua | 无障碍服务过滤事件 → 镜像文件（tmp+rename 原子写）→ EventLib 轮询读取 | engine\...\extension\event\{EventBridge,EventLib} |
| 无障碍进程死后拉活 | system_server 重建服务时 AccessibilityLaunchHelper 顺带复活 WS/保活 | engine\...\accessibility\AccessibilityLaunchHelper |

## 6. 模块地图：engine（C++ 层）

路径前缀：`engine\src\main\cpp\`。

| 目录 | 产物库 | 内容 |
|---|---|---|
| `base\` | `engine_base`（SHARED） | lua_context.cpp（createLuaContext + JNI 栈原语 + LuaObjectAdapter 元表 + per-state 锁）、thread_lib.cpp（全局 `thread` 表，同 state 协程，yield 编码 `(op<<24)|value`）、json_lib.cpp（全局 `json`）、cv_lib.cpp（全局 `cv` + cv.Mat 元表，零依赖 OpenCV 子集 60+ 项）、util.cpp（JNI RAII）、my_log.c、mlua.h（NativeObject 绑定模板） |
| `core\` | `engine_core`（STATIC） | LuaInterpreter（SignalEvent 位信号主循环：execute/interrupt/pause/resume/sleep 挂起释放锁；代码加载链 Provider 分发）、ALEState.h（状态枚举） |
| `extension\` | `extension`（STATIC，**--whole-archive 链入**） | Display.cpp（全局屏函数+图色+vision_extra 包装）、InputManager.cpp（Java/Native 双通道+正态拟人抖动）、JavaInputManager/NativeInputManager（root 直写 /dev/input）、SharedFrame.cpp（共享内存 mmap+seqlock JNI）、VisionBridge.cpp（IDE 图色 C++ 加速 JNI）、vision_extra.cpp（findColorAllPoint/findFeatureAll/findImageAll/getScreenPixel/getScreenFrame）、image_lib.cpp（全局 `images` 表：裁剪/旋转/二值化/PNG/JPEG/Base64）、ws_lib.cpp（全局 `ws` 表，libhv 双向 WebSocket，事件轮询模型）、CMakeLists（libjpeg 12/16-bit OBJECT 变体组装） |
| `remote\` | `remote`（SHARED） | 远端 RPC 服务层：ServiceManager（服务编排+三个 Composite）、CommonService（protobuf 分发+RPC 回调表+ServiceInLua 全局代理）、RemoteService（TcpClient）、FatherService（父控制通道）、DebugService（print 重定向/截图/状态上报）、JsonRPCParser/lua2json；链接 protobuf-lite |
| 根 | `engine`（SHARED → libengine.so） | engine.cpp（JNI 入口 AutoLuaEngineOnLocal_* + AutoLuaEngineService 编排 + LuaStateFactory 注入链）、LuaEnvironmentSetup.h |

链接关系与关键约束（CMakeLists.txt）：
- `engine` = android/log + lua_static + engine_base + engine_core + hv_static + cjson + remote + **`-Wl,--whole-archive extension`**。
- whole-archive 原因：extension 内 JNI 导出（SharedFrame/VisionBridge）无 C++ 调用者，普通静态链会被丢弃 → UnsatisfiedLinkError。
- **新加 C++ 文件注意**：base 无 lua.hpp，用 `extern "C"` 引 lua.h/lauxlib.h/lualib.h（参照 thread_lib）；`aux_source_directory` glob 新增文件需改动 CMakeLists 触发 reconfigure；跨模块依赖方向 base ← extension，故 cv_lib 等需被 base 引用的新库必须放 base。

Lua 环境注入顺序（`createLuaContext` → `LuaStateFactory::create` → `LuaInterpreter::resetLuaState`）：

```
luaL_openlibs
→ thread / json / cv（C++ createLuaContext）
→ ROOT_DIR 全局串
→ autolua_vision（loadImage / CommonBitmap 元表 / FIND_ORDER）
→ Display::injectToLua（屏函数 + compareColor 系 + vision_extra 五函数 + isDisplayDead）
→ InputManager::injectToLua（tap/swipe/keyPress/touchDown/Move/Up/longTap/createPointer/...）
→ images 表 / ws 表
→ postInjectMethodID（Java 侧 compat 注入，必须在 C++ 图色之后）
→ DebugService/FatherService/ServiceManager::setup（RPC 服务全局对象）
→ sleep / require / loadfile / loadresource / exitScript（LuaInterpreter）
→ Java pushLocalServices（14 域服务全局对象 + LuaEnvContributor 回调）
```

## 8. Lua 运行环境与服务注入矩阵

**三个执行环境**：① root 主引擎（Server.kt）② IDE 沙箱（LuaEngineExecutor，由 MainApp 注册）③ 脚本 IDE 调试（同 ①）。**跨三环境 Lua 全局名保持一致是兼容性铁律**——新增服务必须同步三处注册点。

| 注册点 | 位置 | 注册内容 |
|---|---|---|
| root 主引擎 | `engine\core\root\Server.kt` initEngine（:146-194，**顺序敏感**） | http→luajava→LuaEngine→file→device→crypt→app→plugin→ocr→media→ime→mysql→event→virtualDisplay→**compat（必须最后，依赖前序服务）** |
| app 进程（跨进程代理） | `app\...\MainApp.kt` Client.Builder（:107-115） | UI（UserInterfaceImp）、FloatController、IdeLog、uimgr（UiMgrImp 动态 UI，String op 协议）—— 随引擎配置序列化传给 root Server 回放 |
| IDE 沙箱 | `app\...\MainApp.kt`（:122-163）→ LuaEngineExecutor.registerService | 与 root 同款全集 + UI/FloatController/IdeLog + uimgr/uilib + virtualDisplay |
| 无 root 本地引擎 | `app\...\MainApp.kt` buildLocalSandboxEngine（:296-356） | root 拉起失败（无 su）降级：SharedMemoryDisplay（CaptureScreenService 运行时）+ 与 root 同款全集 + UI/FloatController/IdeLog/uimgr/uilib + virtualDisplay |

机制链：`addLocalService(name, 实例, 接口)` → 引擎启动时 `pushLocalServices`（AutoLuaEngineOnLocal :206）包装为 Lua 全局对象 → 若实现 `LuaEnvContributor` 则回调 `contribute(luaContext)` 注册全局函数。

LuaEnvContributor 注入的全局函数/表：

| 服务 | contribute 注入 |
|---|---|
| FileLib | fileExist/mkdir/delfile/fileSize/readFile/writeFile/listDir/zip/unZip |
| DeviceLib | getBrand/getModel/.../readPasteboard/writePasteboard/vibrate 等 20+ |
| CryptoLib | MD5/fileMD5/sha256/encodeBase64/decodeBase64/getFileBase64/encodeUrl/decodeUrl |
| AppLib | runApp/stopApp/appIsRunning/appIsFront/frontAppName/getInstalledApps/exec/execOut/installApk/... |
| MySqlLib | `mysql` 表 + connectSQL/executeQuerySQL/executeSQL/closeSQL |
| MediaLib | `media` 表 + playAudio/stopAudio |
| EventLib | `__event_read` / `__event_enable`（供 compat event 轮询） |
| JavaBridgeLib | import / importClass（返回 LuaClassWrapper） |
| ImeLib / OcrLib / PluginLib | `ime` / `ocr` / `plugin` 表 |
| CompatLib | 执行内嵌 compat.lua（utf8 扩展/图色别名/setTimer/auto.* 工厂/fhttp 组装/autoCollection/event 总线封装/project Fire 热更） |

**跨进程服务限制（重要）**：app 进程实例的服务（UI/FloatController/IdeLog 代理）不能返回 LuaObjectAdapter/Java 对象；需要返回对象的域服务（http/luajava/file/...）必须**在 Lua 所在进程本地注册**——这就是三处注册点存在的原因。

Lua 脚本可调用 API 的权威清单见 [02-Lua-API规范.md](02-Lua-API规范.md)。

## 9. 核心数据流

### 9.1 脚本执行（root 主引擎）

```
VSCode F5 / app 悬浮球
→ [IDE 通道] run_script → ScriptRunDelegate 读文件 → AutoLuaEngineProxy.execute（跨进程）
→ [app 通道] FloatControllerImp → AutoLuaEngineProxy.startTask
→ Server.kt（root 进程）→ AutoLuaEngineOnLocal.execute → JNI executeNative
→ AutoLuaEngineService.execute → LuaInterpreter.execute（SignalEvent 位信号）
→ loop()：luaL_loadbufferx(bootstrap) → lua_pcall → OnStop → 状态广播（kRunning/kIdle）
→ 脚本内 print →（root）IdeLog 代理 → app 进程 IdeServerManager → WS log 帧
                              →（沙箱）IdeLogService 直发
→ 结束 → script_state(idle) 广播
```

### 9.2 截图管线（方案一，详见 features/engine-core/INTEGRATION_PLAN.md §2）

```
APP 模式：MediaProjection → CaptureScreenService(ImageReader maxImages=8)
ROOT 模式：RootScreenshotProvider（隐藏 API/SurfaceControl 反射，免授权）
→ SharedMemoryManager A/B 双缓冲（9 字节自描述头：bufferIndex/w/h）
→ seqlock 写协议（帧计数）→ C++ SharedFrame mmap 读侧 / Lua FFI 读
→ Lua 图色（Display.cpp，帧字节序逐实例 isRgbaOrder 适配）
跨进程：IScreenShareService AIDL 传 fd（ScreenShareServiceImpl dup）
消费端四链：root 主链路 DisplayImplement（建屏走 DisplayControlWrap 双分支，ImageReader 直读）
          / 沙箱 SharedMemoryDisplay（零拷贝 seqlock 读，§2）
          / IDE 图色 VisionJni + 纯 Java fallback（9.5）
          / 按屏 VdFrameClient（virtualDisplay 每屏独立 A/B MemoryFile，fd 经 Shizuku AIDL dup）
```

### 9.3 输入注入降级链（方案二）

```
InjectShellClient 状态机（failure → 下一通道自动降级）：
  A DirectRootChannel   —— uid==0 进程内反射 injectInputEvent
  B RootInjectorChannel —— app_process 常驻子进程 stdin/stdout 行协议
  C ShizukuInjectorChannel —— Shizuku UserService（IInjectorService；含 displayId 定向注入与虚拟屏建屏/帧泵/按屏拉起，versionTag 3）

  / NativeInputManager（root 直写 /dev/input）
```

### 9.4 节点查找（方案三）

```
Lua sel:findOne/find → UiAutomator → 两路：
  同进程：ByMatcher 同步遍历 AccessibilityNodeInfo
  整树 dump：NodeXmlDumper.obtainXml（含旋转坐标修正）
             → AuxDumpServiceLocal 直连 / AuxDumpService AIDL(PFD 流式)

增强层（NodeLib）：rootProvider 接 cachedOrFreshRoot（keepNode 快照缓存）；
  便捷动作主窗口无结果时经 extraRootsProvider 遍历其他窗口兜底；
  getNodeXml/saveNode 节点树 XML 导出（VSCode 抓取节点树面板数据源）
```

```
VSCode find_image/find_multi_color/cmp_color/ocr
→ VisionCommandHandler → VisionJni.nativeFindImage/...（C++ 加速，autolua_vision 复用+行级早退）
```

### 9.6 宿主事件 → Lua event 总线

```
AutoLuaAccessibilityService.onAccessibilityEvent
→ 过滤 toast/notification/click/touch → EventBridge 镜像文件（tmp+rename 原子写，
   宿主 filesDir 固定路径，root uid=0 免权限直读）

```
